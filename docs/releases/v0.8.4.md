# 0.8.4 — `tm aliquot show` carries the tube's events

`tm aliquot show ALQ` now prints the tube's own event trail, so one command answers "what is this
tube, where is it and what happened to it". The release also ships
`tm aliquot label ALQ LABEL [--replace]`, which landed on `main` after 0.8.3 and is part of this tag.

## The tube's events are in `show`

The record gains a final `events` list, oldest first — the same `aliquot_event` rows `tm history`
shows, read in the existing single batch:

```json
{
  "id": "1226L401.1",
  "events": [
    {
      "id": 1,
      "event": "create",
      "at": "2026-11-04 09:12:01",
      "amount": "500.000000",
      "unit": "ul",
      "from_box_id": null, "from_box": null, "from_slot": null,
      "to_box_id": "5b11…", "to_box": "WFL-12-01", "to_slot": "A1",
      "old_status": null, "new_status": "stored",
      "forced": false, "actor": "flmaximwang", "purpose": null, "note": null
    }
  ]
}
```

- Every event carries `id`, `event`, `at`, `amount`, `unit`, `from_box_id`/`from_box`,
  `from_slot`, `to_box_id`/`to_box`, `to_slot`, `old_status`, `new_status`, `forced` (a bool),
  `actor`, `purpose` and `note`. `from_box`/`to_box` are the box **names**, falling back to the id
  when the box row is gone. A tube with no events returns `[]`.
- The events ride in the same `query_many` batch as the rest of the record: showing a tube still
  costs two `dolt sql` processes, whatever the length of its trail.
- Text output keeps the field block and the `path:` line, then prints `events  N` and one line per
  event, oldest first. The line is rendered by the same `event_line` helper `tm history` uses, so
  the two commands never drift apart.
- `--format csv` stays the flat single-row record and drops the events (they are rows, not a cell);
  event rows are `tm history ALQ --format csv`.
- `tm aliquot list --json` keeps the shape it had: the show record **without** `events`. A list
  never reads every tube's event trail, so it pays no per-tube round trip.
- The Dolt commits stay in `tm history`: `show` carries events only. The command is read-only and
  changes no ledger format — `spec_version` stays 6.

```console
$ tm aliquot show 1226L401.1
id          1226L401.1
…
in_stock    true
path: WFL-12-01:A2
events  3
  2026-11-04 09:12:01 create amount=500.000000 ul to=WFL-12-01:A1 status=stored by=flmaximwang
  2026-11-04 09:20:44 move from=WFL-12-01:A1 to=WFL-12-01:A2 status=stored by=flmaximwang
  2026-11-04 09:31:02 use amount=100.000000 ul status=stored by=flmaximwang
```

## `tm aliquot label`: name the tube

`tm aliquot label ALQ LABEL` sets the tube's `label`; the value is trimmed, must not be empty and is
limited to the column's 255 characters. A tube without a label simply gets one.

```sh
tm aliquot label ALQ T-1                 # a tube without a label
tm aliquot label ALQ T-2 --replace       # old label T-1 kept as an alias
```

- A tube that already carries a **different** label is refused (exit 1, nothing written) unless
  `--replace` is given. Then the old label becomes an alias of the aliquot — it still resolves the
  tube — and the new label is set, in one commit: `label(aliquot): <id>`.
- Naming the label the tube already has is a usage error, not a no-op commit.
- `--json` returns `{object, id, label, old_label, aliases}`; the write lock and the global
  `--dry-run`/`--no-commit` behave like every other write command. Python API:
  `ledger.aliquots.label(ref, label, replace=…)`.

## Upgrade

Nothing to migrate: `spec_version` stays 6 and the ledger format is unchanged. A ledger written by
0.8.3 opens unchanged. Both changes are additive at the write side; a consumer that parses
`tm aliquot show` text or JSON sees a new trailing event section and a new `events` key.
