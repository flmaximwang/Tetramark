# 0.8.15 — ask the CLI which skill copy describes it

`tm skill path` and `tm skill version` answer the question a stale skill copy raises: where is the
copy this checkout ships, and does its stated version match the binary in hand? `tm skill version
--file` checks any other copy — a 0.4-era export, for example — and warns instead of failing. This
release also documents the two commands and turns "every command the skills mention must exist" into
a fast-lane test that sweeps the documented invocations against the real CLI. Additive for the ledger
and the existing CLI: nothing breaks and nothing needs migrating; a mismatch is a warning, and only
`tm skill version` emits it.

## Two ledger-free commands

```sh
tm skill path [NAME] [--json]                          # printed: the bare directory
tm skill version [NAME] [--file PATH] [--json]
```

- `NAME` is `tetramark` (the default) or `tetramark-schema`. A copy resolves from
  `$TETRAMARK_SKILLS_DIR`, then the checkout's `skills/`, then installed package data (once the wheel
  ships skills; Tetramark-bfq). `path --json` adds `source`: `env`, `checkout` or `package`; a name
  that no root holds exits 1 and names all three roots.
- `version` prints `skill <v> (<SKILL.md>); tm <v>; match|mismatch`; `--json` gives `name`,
  `skill_version`, `skill_path`, `tm_version`, `match`. On the shipped copy of this release both
  numbers are 0.8.15 and stderr is empty.
- `--file PATH` (a `SKILL.md` or its directory) checks another copy. A stale `0.4.1` copy warns
  `skill 0.4.1 describes an older CLI than tm 0.8.15; use the copy at $(tm skill path) instead` on
  stderr and still exits 0; a versionless copy warns that it predates versioned skills, with
  `skill_version: null` and `match: false`; a version that is not dotted numeric warns that it is not
  comparable. Only a missing file or a file without YAML frontmatter exits 1.
- Neither command resolves or opens a ledger, so both work outside a ledger directory. No other
  command warns about a stale skill.

## Documented commands, swept in the fast lane

`tests/test_skill_commands_exist.py` extracts every `tm` invocation from the fenced code blocks and
inline code of `skills/**/*.md` and resolves its command path against `typer.main.get_command(app)`
(the groups are duck-typed on `.commands`; click is not importable with typer 0.27.3). It expands
`a|b` / `a\|b` alternations, skips bracket forms such as `[--ledger|-l PATH]`, and consumes the
value-taking global options `-l/--ledger`, `-b/--branch` and `-f/--format`. Two narrow literal rules
cover what the tree walk cannot: `--ledger NAME` / `-l NAME` is banned anywhere (0.4's ledger-name
form; `--ledger PATH` stays), and `workspace.yaml` is banned only inside fenced code blocks (the
prose that explains the removed file is intentional). The current tree: **342 documented
invocations**, **76 with alternation/bracket syntax**, **4 skipped**, **0 misses**. `tm server
status`, `tm -w ...`, `--ledger NAME` and a fenced `workspace.yaml` each fail the sweep, verified
against synthetic text so no broken skill text is committed.

The commands are documented in `docs/spec/06-cli.md` §6.5 and the Setup panel listing,
`skills/tetramark/references/commands.md`, and the two skill entries in the README.

## Upgrade

Nothing to migrate. No existing command changed behaviour, and no preset, ledger format or status set
moved; the skill frontmatter is only re-stamped to 0.8.15. A copy that describes an older CLI now says
so instead of erroring on its first removed command.
