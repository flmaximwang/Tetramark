# 0.7.2 — `tm aliquot list`: find the tubes an experiment can use

`tm aliquot list` enumerates tubes. With no filter it prints only the tubes that are physically in
stock — the "what can an experiment use" view — and `--all` / `--not-in-stock` / `--status` open up
the history. `--box` takes a box and everything nested inside it, `--kind` a stock kind, `[STOCK]`
one stock. The `--json` rows are exactly the `tm aliquot show` record, so a list row and a single
tube can be handled by the same code.

CLI-only: no ledger format change (`spec_version` stays 5), nothing to migrate.

## The new verb

```sh
tm aliquot list [STOCK] [--kind KIND] [--box NAME] [--status S ...] \
  [--all | --not-in-stock] [--where FIELD=VALUE ...] [--json]
```

```
$ tm aliquot list
id          stock_kind          status  quantity    unit  label  path
1226L401.1  bacterial_glycerol  stored  500.000000  ul           WFL-12-01:A1
1226L402.2  bacterial_glycerol  stored  200.000000  ul           WFL-12-01:B1
```

- **In stock by default.** A list is the availability view: tubes that left stock (consumed,
  missing, thawed, ...) stay hidden until `--all`, `--not-in-stock` or an explicit `--status` asks
  for them. Naming a status turns the implicit shelf scope off, so `--status missing` is the audit.
- `--all` is every status; `--not-in-stock` only the complement; both together is a usage error.
  `--status` is repeatable (OR); with `--not-in-stock` it intersects.
- `[STOCK]` is one stock id/alias (the unique-prefix rule applies; child stocks are not followed).
  `--kind` is a stock kind. `--box` is a box name/id/alias and includes every box nested inside it.
- `--where FIELD=VALUE` matches aliquot core columns exactly and ANDs with the other filters.
  `status` is filtered with `--status`; `--where status=…` is a usage error that says so.
- The table and CSV print `id stock_kind status quantity unit label path`; `path` is
  `Freezer-1/Shelf-2/Box:A3` (slot included) and empty when the tube is not in stock. Aliquot ids
  are never shortened. `--json` prints the full `tm aliquot show` record per tube — the sorted
  aliases, the stock kind/entity, the box/slot, the path and the derived `in_stock` flag.
- Rows are ordered by stock id then numeric seq. Unknown refs are not-found errors (exit 1); bad
  filters are usage errors (exit 2).

`tm stock show` is unchanged: its embedded aliquot rows stay compact, and its help now points at
`tm aliquot list STOCK` for the rich per-stock listing.

## The rule behind it

Spec §6 now records the convention this settles: **a list verb defaults to what is available**.
When an object has an availability notion, its `list` prints what can be used now, not the whole
history; future list verbs follow the same rule. The entity/stock/box lists have no availability
notion and keep printing every row.

## Python API

`ledger.aliquots.ls(stock=None, *, kind=None, box=None, status=(), in_stock=None,
all_statuses=False, where=())` mirrors the command and returns the same records as
`ledger.aliquots.show`.

## Upgrade

Nothing to migrate. A 0.7.1 ledger opens unchanged under 0.7.2; `spec_version` stays 5.
