# 0.8.24 — document `--where FIELD=` as the empty-field filter

This release is documentation only. 0.8.22 made `field=` select empty fields in
`tm entity list`, `tm stock list`, `tm box list` and `tm find --where`; 0.8.23 gave
`tm aliquot list --where` the same meaning. The spec, the `core/filters.py` module
docstring, the command-reference skill, `SKILL.md`'s filter row and the five `--where`
help strings now describe that meaning: `field=` (an empty value) selects the rows
whose field is empty — `NULL` or `''` on a text-like column, `NULL` only on a
non-text column (kind `int`/`decimal`/`bool`/`date`/`datetime` and core `created_at`),
so a stored `0` is not empty. The empty value skips schema coercion and alias
resolution, `none`/`null` stay literal, whitespace-only values are not special, and
`field~.` is how to ask for "not empty". "`NULL` never matches" now applies to `~`
patterns only.

No command, Python API, SQL or ledger format changed, and no test changed.

## What changed

- **`docs/spec/06-cli.md` §6.4.** The `field=value` section describes the empty value
  (type-aware `NULL`/`''`, no coercion or alias resolution, literal `none`/`null`,
  whitespace not special, `field~.` for "not empty"), and the "`NULL` never matches"
  sentence is restricted to `~` patterns. The `tm aliquot list --where` paragraph
  gains the same empty meaning, with `seq`, `quantity` and `created_at` matching
  `NULL` only.
- **`src/tetramark/core/filters.py` docstring only.** The rules list splits `=` from
  `~` for `NULL`, documents the type-aware empty filter, and records that a Python
  mapping value `None` or `""` means "is empty". No code changed.
- **`skills/tetramark/references/commands.md`.** The FILTER bullets gain the empty
  meaning, the type-aware column lists, the literal/whitespace caveats, the
  `field~.` idiom, the `None`/`""` mapping form, and the `~`-only `NULL` rule; the
  aliquot `--where` section states the empty meaning for its core columns.
- **`skills/tetramark/SKILL.md`.** The filter row folds in `field=` = empty; the file
  stays at 150 lines.
- **Five `--where` help strings.** `tm entity list`, `tm stock list`, `tm box list`,
  `tm find` and `tm aliquot list` now say `FIELD= matches empty`.

## Upgrade

Nothing to migrate: `spec_version` stays 6, the ledger format is unchanged, and every
command behaves as it did in 0.8.23. A ledger written by any 0.8.x release opens
unchanged. This release only makes the documented behaviour match the code.
