# 0.8.48 — notes in the `stock`, `entity` and `box` list tables

`tm stock list`, `tm entity list` and `tm box list` now end with a `notes`
column, always shown. It is the last column, so the existing columns keep their
order and any script that reads the leading fields is unaffected. The column
answers the question the lists were worst at: with several similar stocks, the
note is what tells them apart without running `tm stock show` on each one.

The table shows a **one-line preview**, not the note:

- `None`, an empty note and a note of only blank lines print an empty cell.
- The first non-empty line is taken (leading blank lines are skipped) and
  whitespace-stripped.
- A line longer than 40 terminal cells is cut at 40 and gets `…`. The width is
  measured with `rich.cells.cell_len`, so CJK and Greek text keeps its alignment,
  and the cut never splits a wide character or a combining sequence. A line of
  exactly 40 cells is not cut.
- When N further non-empty lines follow, ` (+N lines)` is appended; blank lines
  are not counted.

So a note of `first line\nsecond line` prints `first line (+1 lines)`, and a
60-cell first line with two more lines prints 40 cells, `…` and ` (+2 lines)`.

This is a **table-only** shortening. `tm stock show`, `tm entity show`,
`tm box show`, `--json` and `--format csv` keep the full note, unchanged.

```console
$ tm stock list
id        kind  entity_id  entity_name  aliquots_in_stock  status  notes
7701AB03  lot   22222222   pUC19-prep   1                  active  miniprep 2026-11-07; keep at -20 (+1 lines)
```

## What changed

- `src/tetramark/cli/output.py`: one shared formatter, `notes_cell`, plus the
  `NOTES_COLUMNS` set it is keyed on. Only `_table` consults it; `_cell` (used
  by `show` and CSV) and the JSON dump are untouched. The set lets a later
  command reuse the formatter for a notes-like column (the planned aliquot
  `stock_notes`) without a second implementation.
- `src/tetramark/cli/stock.py`, `entity.py`, `box.py`: `notes` appended to the
  list commands' `columns`.
- `tests/test_list_notes_column.py`: fast-lane formatter tests (blank forms,
  leading blanks, 40 vs 41 cells, multi-line suffix count, 6×His, CJK/Greek,
  trailing spaces, tabs) and real-ledger tests that the three tables end with
  `notes`, the table shows the preview, and JSON/CSV keep the full note.
- `tests/test_list_tables_golden.py` and the four `tests/data/golden/*.table`
  files: the stock, entity and box fixtures now carry a two-line note, a note
  wider than 40 cells and a CJK/Greek note, so the goldens pin the preview.
- `tests/test_stock_list_scope.py`, `tests/test_read_side.py`: the expected
  column sets and CSV header gained `notes`.
- `docs/spec/06-cli.md`, the tetramark skill (`references/commands.md`,
  `references/recipes.md`): the list-column descriptions state the new last
  column and the preview rule.

## Upgrade

Nothing to migrate: no schema, preset, migration step or ledger format changed,
`spec_version` stays 7, and every record already carried `notes`. A consumer
that parses the human table by column position rather than by header should
read the header instead — the new column is appended, never inserted.
