# 0.6.0 — interactive add-form

`tm entity|stock|aliquot|box add-form` opens a form that asks for the kind, the
preset's fields, the box and the slots, and writes the same row as the
flag-based `tm <obj> add`. The form is for people; agents keep using `add`, and
scripts are unaffected because the form refuses to run without a terminal. The
release also adds the read-only `long: true` preset key. It is a **CLI plus
preset-metadata** release: ledgers, schema and data are untouched
(`spec_version` stays 5), so nothing has to migrate.

## The form

| Command | What it creates |
|---|---|
| `tm entity add-form` | an entity of a chosen kind |
| `tm stock add-form` | a stock, its kind fields and its first aliquot(s) |
| `tm aliquot add-form` | more aliquots for an existing stock |
| `tm box add-form` | a box (optionally nested in another box) |

The first step is always the numbered kind list from the ledger's effective
schema (an aliquot form lists the **stock** kinds). Then come the kind's fields
in schema order with their descriptions and `*` for required; computed fields
are never asked, sequence fields are. Values are checked as they are entered:
enum by number or value, bool `y`/`n`, dates as ISO or `today`/`now` with
`today`/`now` for datetimes, ints and decimals parsed, patterns checked, and a
ref is resolved immediately with its name shown back (`?term` searches like
`tm find` and you pick a result by number). Aliases and slots are one per line
or comma-separated. The stock form then asks for the aliquot count, the box
(`?` lists the boxes) and the slots, pre-filled with the next free ones.

`Enter` moves on (skipping an optional field or accepting its default, while a
required empty field stays with "required"), `Shift+Tab` goes back with the
value pre-filled, `Tab` completes enum values and ref ids/aliases,
`Alt+Enter`/`Ctrl+J` insert a newline, `Ctrl+E` edits the current field in
`$VISUAL` → `$EDITOR` → `vi`, `Ctrl+C` aborts, and a footer lists the keys. The
review screen numbers every value; a number jumps back, `y` writes, `q`
cancels. The write lock is taken only on `y`, and the write is the same
`ledger.<objects>.add(...)` as `add` (same message, `--dry-run`/`--no-commit`/
`--json`, one commit).

## `long: true`

`long: true` marks a `string`, `text` or `sequence` field whose value can be
large. The form then never shows the value in full: it renders
`[pasted 5,432 chars · 12 lines · ATGCGTACGT…TTAGCCGGAA]`, accepts a bracketed
paste directly (pasting again replaces, Backspace on the placeholder clears)
and submits the full text. The key is read-only metadata: no DDL, excluded from
the schema fingerprint (like `description`), no preset `version:` bump and no
migration; `tm schema show` displays it, and the bundled presets now mark their
text and sequence fields.

## Highlights

- Four new commands: `tm entity|stock|aliquot|box add-form`; no positional
  argument, no flags — every question comes from the ledger's schema.
- The form writes through the same core `add` as the flag-based command, so the
  stored row, the commit and the printed message are identical.
- Without a terminal it refuses with exit 2 and points at `tm <obj> add`;
  agents and scripts keep using `add`.
- `long: true` is a new read-only preset key, set in the bundled presets on
  every text/sequence field; existing ledgers keep their copied presets and
  simply do not get the short form until they add the key.
- New runtime dependency: `prompt_toolkit` (the form's input layer). `dolt`
  (>= 2.3.5) is unchanged.
- Unchanged on purpose: the ledger format, `spec_version` 5, the schema, the
  presets' versions, the Python API and every existing command.
