# 0.8.20 — `tm box edit` and rename-only names

`tm box edit REF [--set field=value ...] [--json]` gives boxes the edit surface every other core
object already had, and `name` becomes rename-only for entity and box: an edit can no longer
write a name behind the back of `tm entity rename` / `tm box rename`. Boxes were the last core
object with no edit verb: box notes were settable only at `tm box add`, and a box kind's own
fields had no write path at all. `tm entity edit` and `tm stock edit` keep their shape. One
deliberate break: `tm entity edit --set name=…` now exits 2 and points at `tm entity rename`;
nothing else breaks and nothing needs migrating.

## What changed

- **New: `tm box edit REF [--set field=value ...] [--json]`.** It edits one box, resolved like
  `tm box show` (its name, its id or an alias). It takes `notes` (free text) and every field the
  box's kind declares in `box_<kind>`, coerced and validated exactly as at add time — a value the
  kind would refuse at add time is refused here too. The human line reads
  `Edited box <name> (<kind>)`.
- **`name` is rename-only.** `tm entity edit --set name=…` and `tm box edit --set name=…` are
  refused with a usage error (exit 2) that points at `tm entity rename` / `tm box rename`. A name
  changes only through `rename`, which keeps the old name as an alias (and rebuilds a box's
  `v_box_<name>` view); a plain column update cannot do that. `tm stock edit` is unchanged — a
  stock has no name.
- **The allowlist is split in two.** `_CORE_ON_ADD` (`entity`: `name`, `notes`; `stock`: `notes`;
  `box`: `name`, `notes`) still feeds the create paths and the CSV import, while `_CORE_EDITABLE`
  (`entity`: `notes`; `stock`: `notes`; `box`: `notes`) is the only list an edit consults. Add and
  import keep accepting `name`; an edit never does. The rule lives in the core, not only in the
  CLI.
- **Structural fields are refused.** `id`, `kind` and `created_at` are identity and creation data
  and are refused for every object; a box's `parent_box_id` and `parent_slot` are refused too and
  point at `tm box move REF --in PARENT [--slot S]`.
- **One edit is one Dolt commit** (`edit(box): <summary>`, `edit(entity): <summary>`), `--json`
  returns the loaded record and the global `--dry-run` writes nothing.
- **An empty value now clears a column.** `--set field=` (the value exactly empty) sets an
  optional column to NULL for entity, stock and box edits; a required field cannot be cleared and
  is refused. A whitespace-only value is not empty: it is coerced like any other value, never
  cleared.

## Upgrade

Nothing to migrate: `spec_version` stays 6 and the ledger format is unchanged. A ledger written by
any 0.8.x release opens unchanged, and no preset changes.
