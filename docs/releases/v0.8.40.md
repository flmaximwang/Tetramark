# 0.8.40 — the add forms ask every writable creation property

The interactive add forms now cover the whole creation surface of `tm <object> add` instead of only
the kind's own fields. `tm stock add-form` adds optional **parent stock**, **source aliquot** and
**notes** questions, `tm aliquot add-form` adds an optional **creation status** question, and a
`notes` field declared by a kind is never asked twice. Everything else is unchanged: the forms still
collect values and call the same `ledger.<objects>.add(...)`, still write the stock with zero
aliquots, and still print the same message as `add`.

## What changed for people

- **The stock form's steps:** kind → entity → the kind's fields → optional parent stock (a ref with
  search; lineage, the same as `tm stock add --parent`) → optional source aliquot (a ref with
  search; the same as `--source-aliquot`) → optional notes. Parent and source aliquot are
  independent, and a resolved ref shows its name back like every other ref step.
- **The stock write:** `ledger.stocks.add(kind, entity=..., values=..., aliquots=0, parent=...,
  source_aliquot=...)`, with core notes in `values`. The new stock still has no aliquots and the
  successful human write still prints the `Next:` line pointing at the aliquot workflow; skipping a
  new optional step is exactly like omitting its `add` flag.
- **The aliquot form's steps:** kind → stock → count → quantity → unit (only with a quantity) →
  box → slots → optional creation status. The status step lists exactly the stock kind's set in its
  own order, picked by number or name. Enter keeps the add command's placement default: a placed
  tube takes the first of `stored`/`pending` the set has, an unplaced tube the first of
  `pending`/`stored`, otherwise the set's first in-stock status, otherwise its first status. The
  help line and docs do not promise `stored`/`pending` for custom or legacy sets that lack them.
- **The aliquot write:** a chosen status is stored and recorded as the create event's `new_status`,
  exactly as `tm aliquot add ... --status`; skipping it is exactly like omitting the flag. Quantity
  and unit behaviour from 0.8.38 is unchanged.
- **No duplicate notes question:** a kind that declares its own `notes` field is asked that field
  in schema order and it is the only notes question (entity, stock and box); otherwise the core
  notes step comes last. `--id` remains an add-only option for back-filling and migration and is
  never asked by a form.

## Upgrade

Nothing to migrate: this is an interactive-form change only. The forms call the existing
`ledger.stocks.add`/`ledger.aliquots.add` signatures and the core's default and placement rules, so
there is no schema, DDL, preset, migration, query or dependency change and no new flag. `tm
<object> add`, the Python API, the stock form's zero-aliquot behaviour (0.8.39) and the aliquot
form's quantity/unit behaviour (0.8.38) are unchanged. The shipped skills are re-stamped to 0.8.40.
