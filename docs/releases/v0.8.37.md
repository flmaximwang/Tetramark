# 0.8.37 — `tm aliquot status` takes `-m/--message`

0.8.28 renamed the event column to `message` and left one naming mismatch behind: `tm aliquot status`
still called its reason `--note`, while `use` and `move` already took `-m/--message`. This release
**removes the old status option** and the matching Python keyword outright — no alias, no shim — so
the write side says the same word as the column and the read side. This is a **breaking CLI and
Python API change**; there is no schema or ledger-format change, and no migration step.

## The breaking change

| before | after |
| --- | --- |
| `tm aliquot status ALQ NEW --note TEXT` | `-m/--message TEXT` |
| `tm aliquot status ALQ NEW --force --note TEXT` | `--force -m TEXT` |
| `ledger.aliquots.status(ref, status, note=...)` | `message=...` (`note=` raises `TypeError`) |

`-m/--message` is optional without `--force`. A given value is trimmed, refused when empty or
whitespace-only, and stored in `aliquot_event.message`; a forced event also records
`aliquot_event.forced = TRUE`. `--force` without a message is a usage error (exit 2), and the former
option is gone completely: Click reports `No such option: --note` (exit 2) and writes nothing.

`tm aliquot move` and `tm aliquot use` are unchanged: both still require `-m/--message`.

## Upgrade

```sh
tm aliquot status ALQ NEW -m "why"
```

Scripts that pass the former option or the Python `note=` keyword must switch to `message=`.
Ledgers need no migration: the `aliquot_event.message` column already exists since spec 7 (0.8.28).
