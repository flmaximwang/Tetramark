# 0.8.46 — embedded reads keep integer types when a `dolt sql-server` is live

A `dolt sql-server` that happens to be running on a ledger directory makes Dolt's CLI auto-route
`dolt sql` through it, and the routed JSON result sets render integer columns as strings (`"1"`
instead of `1`). The embedded driver now restores Python `int` from the same-process `SHOW COLUMNS`
probe, so a read's types no longer depend on whether a server is alive on the directory.
`stocks.ls()`'s `aliquots_total` is an `int` again with and without a live server. No default
backend change, no new dependency (PyMySQL is still optional/server-only), no server management in
product code, and no budget change.

## The routed JSON problem

Dolt's `dolt sql --help` says it plainly: if a server is running for the database, the query goes
through it automatically. There is no flag that disables the routing. The CLI's `-r json` output is
then produced by the server, and integer columns arrive as strings:

| `<db>/.dolt/sql-server.info` | routed? | `SELECT seq` (INT) |
|---|---|---|
| absent | no | `{"seq":1}` |
| live server, reachable | yes | `{"seq":"1"}` |
| file present, pid dead | no (local engine) | `{"seq":1}` |
| file present, pid alive, port refused | no (silent local fallback) | `{"seq":1}` |

DECIMAL is a string in both modes, and CSV output is identical in both modes, so neither can carry
the missing type. The embedded read path already builds an empty temporary table for each
`SELECT`/`WITH` statement (`CREATE TEMPORARY TABLE .. AS SELECT .. LIMIT 0`) and prints
`SHOW COLUMNS` for it in the same `dolt sql` process; the `Type` column of that probe is the
authoritative SQL type of the same result, and it costs no extra process.

## What changed

- `EmbeddedDriver._query_probed` now returns and uses the probe's `Type` column, and restores
  `int` for integer-family columns whose routed value is a string of ASCII signed digits
  (`re.fullmatch(r"-?[0-9]+", value, re.ASCII)`): `tinyint` (including `tinyint(1)`), `smallint`,
  `mediumint`, `int`, `integer`, `bigint`, with optional display width and `unsigned`.
- Nothing is decided from the value alone: `TEXT`/`VARCHAR` holding `"123"` stays a string, DECIMAL
  stays exactly what the local engine returns (`"1.50"`), `NULL` stays `None`, booleans and floats
  are untouched, and `BIGINT UNSIGNED` above `2**63` becomes an exact Python `int`.
- `query(fill_columns=False)` and `query_many(..., fill_columns=False)` still run the same-process
  probe for types but skip NULL filling, so the contract is unchanged (a `NULL` column is absent)
  while integers stay integers. The read is still one `dolt sql` process.
- A pending-transaction preview (`Driver.transaction()` + `query`) appends the same temp-table probe
  after its `ROLLBACK`, in the same process and against the committed schema; the previewed integer
  columns are typed, and the buffer stays pending and rolled back.
- The parser now locates the probe's result sets by generated marker rows instead of a fixed offset:
  a routed session prints an extra `{}` result line for `CREATE TEMPORARY TABLE` (the local engine
  prints none), which is why the old offset-based parse rejected the probe whenever it was routed.
- Non-`SELECT` reads (`SHOW`, `DESCRIBE`, `CALL`, `EXPLAIN`) and statements the probe rejects (e.g.
  duplicate output column names) have no type metadata and keep their historical behaviour: values
  are returned exactly as Dolt reports them, with no heuristic coercion. This is the explicitly
  documented residual and is pinned by a test.

## Measured type matrix (real Dolt 2.6.1)

Local captures were taken with no server; routed captures on the same directory with a live
test-owned `dolt sql-server`, proven active by an INT column returning `"1"`. Probe type is the
`SHOW COLUMNS` `Type` of `CREATE TEMPORARY TABLE .. AS SELECT .. LIMIT 0`.

| Probe type | Local engine | Routed server | 0.8.46 read |
|---|---|---|---|
| `int`, `tinyint(1)`, `smallint`, `mediumint`, `bigint`, `bigint unsigned` | `int` | `str` | `int` (restored) |
| `decimal(10,2)` | `str` | `str` | `str` (unchanged) |
| `text`, `varchar`, `char`, `enum`, `set` | `str` | `str` | `str` (numeric-looking text untouched) |
| `date`, `datetime`, `timestamp` | `str` (ISO) | `str` (ISO) | `str` (unchanged) |
| `float`, `double` (base column) | JSON number (`2.0` → `2`, `2.5` → `2.5`) | `str` | as Dolt reports (documented boundary) |
| `year`, `time`, `bit`, `json` | `int` / `int` ms / `int` / object | `str` / `str` / replacement-char text / JSON text | as Dolt reports (no Tetramark schema emits them) |
| aggregations: `COUNT`, `MIN`/`MAX(int)`, `CAST(.. AS SIGNED)`, `CASE`, `int + int` | `int` | `str` | `int` (restored) |
| `SUM(..)` over an integer column, `AVG`, `COALESCE(SUM(..), 0)` | `int`/`float` | `str` | as Dolt reports (documented boundary) |
| `SUM(decimal)`, `MAX(decimal)`, `int / 2` | `str` | `str` | `str` (unchanged) |

The probe's temp-table `Type` is authoritative for base columns and integer-typed expressions, but
lossy for float/double-derived expressions: a `SUM` over an integer column probes as `double` while
the local engine renders an integer JSON number, and a `SUM` over a `DECIMAL` also probes as
`double` while the local engine renders a decimal string. Coercing `double`-typed values would
therefore corrupt DECIMAL-derived columns (e.g. `quantity_in_stock`); Tetramark's schema never
creates float/double/bit/json/time columns, and its `SUM`-derived count columns cast to `int` in
Python where they are reported (`aliquots_in_stock`, `stocks_available`). Those expressions are left
exactly as Dolt reports them.

## Read contract

`docs/spec/07-driver-layer.md` §"User-run `dolt sql-server`" is the normative text: typed parity for
`query`/`query_many`, `fill_columns=False`, pending-transaction preview, branch sessions, the
residual, and the measured boundary above. The driver still neither starts, stops nor detects a
server; running one is still not a multi-writer mode, and no optional dependency is required.

## Tests

- `tests/test_driver_routed_parity.py` (new, real Dolt): a test-owned `dolt sql-server` started
  through `ServerDriver` and stopped with `discard()`; routing is asserted from a raw
  `dolt sql -r json` string, never assumed (a skip is not allowed). Every case is compared between
  the local engine, the routed server and the post-shutdown local engine, on values and Python
  types: INT NOT NULL, BIGINT, `BIGINT UNSIGNED > 2**63`, tinyint, negative integers,
  numeric-looking TEXT/VARCHAR, DECIMAL, NULL filling, empty results, `COUNT` aggregates, aliased
  expressions, `query_many`, `fill_columns=False`, non-`SELECT`/probe-rejected residual, pending
  preview, branch session, one-process invariant, and the `stocks.ls()` regression with a cached
  server and after `shutdown_all_servers()`.
- `tests/test_driver_type_normalisation.py` (new, fast): type-string parser and value conversion
  with synthetic JSON, including unicode digits, signs, whitespace and non-integer types.
- Existing driver/contract/query-many/branch/transaction tests stay green.
