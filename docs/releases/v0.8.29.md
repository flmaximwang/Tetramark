# 0.8.29 — structured box kind facts in the add-form

At the kind step of `tm box add-form` every box kind now shows its shape under the description it
already had: geometry, resolved row/column or slot labels, slot count, capacity and whether it holds
boxes. Every value comes from the parsed effective schema — no occupancy query runs before a kind is
chosen — and the capacity is the same formula `tm box list` prints. This is additive rendering: the
kind list, its numbering and selection, the error messages, Shift+Tab and the review screen behave
exactly as before, the entity/stock/aliquot forms are untouched, and nothing needs migrating.

## What the kind step shows

The repository's `presets/base.yaml` renders the box kinds like this (each keeps its description
line; the other four kinds follow the same pattern):

```
  4. grid9x9  Nine-by-nine tube box (rows A-J without I, columns 1-9).
       geometry: grid, 9 rows × 9 columns
       rows: A B C D E F G H J (9)
       columns: 1 2 3 4 5 6 7 8 9 (9)
       slots: A1 … J9 (81)
       capacity: 81 aliquots (81 slots × 1 per slot)
       holds boxes: no
```

- `grid` shows the **resolved** row and column labels (an exclusion such as `A-J!I` appears as
  `A B C D E F G H J`), the first and last slot, and the capacity. `named` lists its slot labels and
  capacity. `slotless` shows the configured aliquots-plus-child-boxes capacity, or
  `capacity: unlimited`, and never a `slot_capacity` row.
- A label list of 12 or fewer is shown in full; a longer one shows the first 8, `…`, the last 2 and
  `(N)`, as in `1 2 3 4 5 6 7 8 … 383 384 (384)`. Grid `slots` always shows `first … last (N)`.
  Labels are printed verbatim and never truncated — a label such as `<b>&{row}` stays literal text.
- `holds boxes` is structural: a grid box can never nest a child box, a named box holds one per free
  slot, and a slotless box holds boxes directly.
- `slot_capacity` greater than 1 shows through: with 96 slots and `slot_capacity: 2` the row is
  `capacity: 192 aliquots (96 slots × 2 per slot)`.

Entity/stock/aliquot kind lists, search hits and box lists render exactly as they did.

## Upgrade

Nothing to migrate. This is rendering only: no schema, DDL, preset, migration, query or dependency
change, and `tm box add-form` writes exactly the row `tm box add` writes. The shipped skills are
re-stamped to 0.8.29.
