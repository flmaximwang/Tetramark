# 0.7.0 — batched Dolt access: commands ~10× faster

Every `tm` command now reaches Dolt in a handful of batched `dolt sql` runs
instead of one process per statement. Output, plans, CSV bytes, commit messages
and exit codes are unchanged. Ledgers, schema, presets and data are untouched
(`spec_version` stays 5), so nothing has to migrate.

## Speed

The embedded driver used to start one `dolt sql` process per statement, and
whole operations were many independent statements. Reads and writes are now
batched (`Driver.query_many` / `execute_many`):

| Operation | 0.6.1 | 0.7.0 |
|---|---|---|
| `tm find` (lab ledger, `find gammaPFD`) | 6.8 s | **0.7 s** |
| `tm init` (base preset) | 35 processes / ~20 s | 3 processes / ~2 s |
| `tm schema plan` | 64 processes / ~35 s | 3 processes / ~1 s |
| `tm entity list` / `tm box show` | 11 / 9 processes | 3 / 3 processes |
| CSV import / export | 53 / 33 processes | 4 / 2 processes |
| lineage / history | 20 / 20 reads | 6 / 4 reads |
| one write session | 3 processes | 2 processes |

## Highlights

- `tm find` searches the whole ledger in one batched read (#14).
- find, list, show, lineage, history, CSV import/export, schema
  introspection, open/adopt/status/check and write sessions are all batched
  (#15).
- show, history and lineage read only the resolved object's kind tables, so a
  kind that is declared but not yet applied no longer breaks them for other
  objects.
- `tm entity|stock|box show ""` is rejected again instead of resolving to the
  only object of a one-object ledger.
- New opt-in `ServerDriver` (`TETRAMARK_DRIVER=server`): one real
  `dolt sql-server` per ledger, reused across statements. It is used by the
  test suite; the **product default stays the embedded driver**, and
  `pymysql` is a dev-only dependency.

## Test suite

- A plain `uv run pytest` runs the whole suite against real Dolt, both
  backends, with no skips added to save time.
- The suite enforces its own time budget: the run fails past **300 s**
  (`-m fast`: 30 s), and every test has a 60 s timeout (`pytest-timeout`).
  `TETRAMARK_SUITE_BUDGET_SECONDS` overrides the budget for profiling.

## Upgrade

Nothing to migrate. A 0.6.1 ledger opens unchanged under 0.7.0.
