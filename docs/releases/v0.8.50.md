# 0.8.50 — the owning stock's note in `tm aliquot list` and `tm aliquot show`

An aliquot has no note of its own worth reading: it borrows the owning stock's
note. Ticket 0.8.48 showed the stock's note in the stock, entity and box lists;
this release shows the same note from the tube's side, without a second command
and without leaving the tube's row.

The note is not the tube's own property, so it wears the `*` convention the
related lines already use (a `*` marks a value that does not come from the
object's properties):

```console
$ tm aliquot list --where 'stock_notes~miniprep'
id          stock_kind  status  quantity  unit  label  path    *notes
0826FP01.1  lot         stored  500.000000 ul           FR-1:A1 miniprep 2026-11-07; keep at -20 (+1 lines)
0826FP01.2  lot         stored  500.000000 ul           FR-1:A2 miniprep 2026-11-07; keep at -20 (+1 lines)

$ tm aliquot show 0826FP01.1
id          0826FP01.1
...
notes       <the tube's own notes column, still present for now>
* notes     miniprep 2026-11-07; keep at -20 C
            do not refreeze
...
* entity          plasmid · pUC19
* inherited from stock 0826FP01
path: FR-1:A1
events  1
...
```

**The list.** `tm aliquot list` appends `stock_notes` as its last column. The
human table header is `*notes` (no space, so the column keeps its width) and
the cell is the same one-line preview the stock/entity/box lists use: the first
non-empty line, whitespace-stripped, cut at 40 terminal cells with `…` when
longer, plus ` (+N lines)` for the further non-empty lines. Every row repeats
its stock's note — two tubes of one stock show it twice, never a blanked
repeat. `--json` and `--format csv` keep the clean field name `stock_notes`
and the full untruncated text; the tube's own `notes` field stays in the record
for now (a later ticket drops it).

**The show.** `tm aliquot show` gains a `* notes` key/value row carrying the
**full** note (show never truncates) and, after the `* entity` line, a
`* inherited from stock <id>` line naming the stock the note belongs to, before
the `path:` line and the events section. JSON keeps `stock_notes` (full, no
star) and the CSV flat record gains it with the clean name.

**The filter.** `--where stock_notes~…` (and `--where-any`, and the Python
`where=` / `where_any=`) filters the owning stock's note. It rides the shared
filter backend: `=`, `~`, `!=`, `!~`, `<`, `<=`, `>`, `>=` all work, an empty
value (`stock_notes=`) applies the text-column empty rule (`NULL` or `''`), and
an ordered comparison uses the database's collation order. `notes` keeps
meaning the aliquot's own column.

## What changed

- `src/tetramark/core/objects.py`: `list_aliquots` selects `s.`notes` AS
  `stock_notes`` in its existing stock join and puts it in the record; the
  `stock_notes` filter field maps to `s.`notes`` (the other fields still map to
  the aliquot row), and `_CORE_FILTERS["aliquot"]` lists it. `show_aliquot`
  adds `s.`notes`` to the stock batch query it already runs — no new round trip
  — and puts `stock_notes` in the record.
- `src/tetramark/cli/aliquot.py`: `stock_notes` is the last
  `ALIQUOT_LIST_COLUMNS` entry with the `*notes` table header; the show text
  record labels it `* notes`, and the show command prints the
  `* inherited from stock <id>` line after the related lines.
- `src/tetramark/cli/output.py`: `stock_notes` joins `NOTES_COLUMNS` (so the
  shared preview applies) and `emit_read` accepts a table-only header map,
  keeping the CSV/JSON field names clean.
- `tests/test_aliquot_stock_notes.py` (new): the `*notes` header, the preview
  and the repeated rows, the show label/footer, the full JSON/CSV text and the
  `stock_notes`/`notes` filters.
- `tests/test_list_tables_golden.py` + `tests/data/golden/aliquot_list.table`:
  a new golden pins the list columns and the three note shapes (two-line, wider
  than 40 cells, CJK/Greek).
- `tests/test_aliquot_show_golden.py` + the three
  `tests/data/golden/aliquot_show_*.json`: the fixtures now set a stock note, so
  every show golden pins its `stock_notes` value.
- `tests/test_cli_objects.py`, `tests/test_aliquot_where_operators.py`,
  `tests/test_show_related_aliquot.py`, `tests/test_docs_commands.py`: the
  expected record key sets, table/CSV column sets and text-output predicates
  gain the new field and its `*` lines.
- `docs/spec/06-cli.md`, `README.md`, the tetramark skill (`references/
  commands.md`, `references/recipes.md`): the aliquot record, list columns,
  show order and filter allowlist document `stock_notes`.

## Upgrade

Nothing to migrate: no schema, preset, migration step or ledger format changed,
`spec_version` stays 7, and every stock already carried `notes`. A consumer that
parses the human table by column position rather than by header should read the
header instead — `stock_notes` is appended, never inserted. The JSON record and
the show CSV gain one additive field.
