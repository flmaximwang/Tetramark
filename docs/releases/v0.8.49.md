# 0.8.49 — write stock notes in your editor: `tm stock note`

A stock's core `notes` column already existed, but writing a multi-line note meant
shell quoting a `--set notes=…` value. `tm stock note REF [TEXT] [--append] [--clear]`
writes it in `$VISUAL`/`$EDITOR` instead, appends one more line, or clears it. It is
CLI-only: no schema change, no migration, `spec_version` stays 7.

```sh
tm stock note 7726KU07                 # open the current note in $VISUAL/$EDITOR/vi
tm stock note 7726KU07 --append "thawed once, keep on ice"
tm stock note 7726KU07 --append        # empty buffer; its result is appended
tm stock note 7726KU07 --clear
```

The note is the core column, so it is already visible in `tm stock show`, `--json`,
`--format csv` and the `notes~…` filter — this command only changes how it is written.

## The command

- A bare `REF` opens the current note in `$VISUAL`, then `$EDITOR`, then `vi`, with a
  git-style scissors line under the value; everything from that line down is stripped
  when the file comes back, while lines starting with `#` are kept as note text. A
  buffer that comes back unchanged prints exactly `no changes`, exits 0 and writes
  nothing (no commit).
- `--append TEXT` adds `TEXT` as one more line. The separator is a single `"\n"` and it
  is omitted when the current note is empty or NULL, so the first append never starts
  the note with a blank line. A bare `--append` opens an **empty** buffer and appends
  its result; an empty result there changes nothing (`no changes`).
- `--clear` sets the notes to `NULL`. An empty result **without** `--clear` is a usage
  error (exit 2) pointing at `--clear`, so a stray `:wq` cannot wipe a note by accident.
- `TEXT` is a **positional** argument (before or after `--append`) because typer 0.27.3
  cannot express an option with an optional value: `flag_value` is ignored and plain
  `click` is not importable. The documented invocations are unchanged:
  `tm stock note REF --append "text"` appends `text`, bare `tm stock note REF --append`
  opens the empty editor. `TEXT` without `--append` and `--append` with `--clear` are
  usage errors.
- `REF` resolves exactly as `tm stock edit` resolves it: full id, exact alias, or a
  unique id prefix; an ambiguous prefix is a usage error naming the candidates.
- One call is one write session and one Dolt commit (`edit(stock): <kind> <id>`; the
  note text stays out of the ASCII-only summary). The human line is the same as
  `tm stock edit` (`Edited stock <kind> <id>`), `--json` (local or global) prints the
  loaded record, and `--dry-run` prints the buffered `UPDATE` and writes nothing.

The generic writer behind it is `note_object(...)` in `src/tetramark/core/objects.py`
(entity, stock and box, with the box resolved by name first) and the
`ledger.stocks.note(...)` facade; the `tm entity note` and `tm box note` commands come
in the next ticket.

## What changed

- `src/tetramark/core/objects.py`: `note_object()` and its `_append_note()` helper —
  one write session, in-session read of the current note for append, `UPDATE` to the
  new value (NULL when cleared) and a reloaded record; `StockOps.note()` delegates to
  it.
- `src/tetramark/form/editor.py`: the file/editor plumbing of `edit_value` moved into
  one private `_edit_buffer`, and `plain_editor_text()` / `edit_plain_text()` edit free
  text without a form `Step` (injectable `run=`, scissors metadata, `unlink` in
  `finally`). `edit_value` is unchanged for its callers.
- `src/tetramark/cli/stock.py`: the `note` command and its editor wrapper; the stock help panel order is now add, add-form, aliquot, show, list, edit,
  note, renumber, purge.
- `docs/spec/06-cli.md` and `skills/tetramark/references/commands.md`; the release
  notes you are reading.
- `tests/test_stock_note.py` (19 tests: Dolt-free editor/argument tests in the fast
  lane, real-Dolt API and CLI tests for save, unchanged, empty, clear, append,
  ambiguity, one commit, `--json` and `--dry-run`) and the pinned stock subcommand
  order in `tests/test_cli_panels.py`.

## Upgrade

Nothing to migrate: no schema, preset, migration step or ledger format changed, and no
existing command changes meaning. `spec_version` stays 7.
