# 0.8.18 — the wheel ships the skills and every release carries its wheel

An installed `tm` is now something an agent can rely on end to end: the wheel ships both skills as
package data (`tetramark/skills/`), every release publishes the wheel and the sdist as release
assets, and the install commands are pinned to a release tag instead of a checkout. `tm skill path`
works from the installed wheel with no source tree. Additive: the CLI, the schema, the presets and
the ledger format are unchanged and nothing needs migrating.

## What changed

- **The wheel ships the skills.** `pyproject.toml` force-includes `skills/` as
  `tetramark/skills/` next to the presets, and the sdist lists it too (`uv build` builds the wheel
  from the sdist, so a missing directory cannot silently disappear). An installed `tm skill path`
  finds `<site-packages>/tetramark/skills/tetramark`, and `tm skill version` compares its stamp
  with `tm --version`.
- **Each release carries its distributions.** After the tag and the GitHub release are created, the
  release workflow runs `uv build` in the runner's temp directory, requires exactly
  `tetramark-<version>-py3-none-any.whl` and `tetramark-<version>.tar.gz`, and attaches the ones the
  release is missing. It is idempotent: existing assets are skipped (one `::notice::` per skip), a
  re-run or `workflow_dispatch` backfill never replaces a published file, and `dry_run` builds but
  uploads nothing.
- **Install docs are pinned and verified.** The README installs the pinned tag
  `uv tool install --reinstall "git+https://github.com/flmaximwang/Tetramark@v0.8.18"`, offers the
  release-asset wheel URL as the single-file alternative, labels `uv tool install -e .` as
  development-only, and documents an upgrade as the same command with the new tag. A troubleshooting
  section covers the foreign-`PYTHONPATH` line, the `tm --version` drift warning, running from
  `$HOME` and `tm skill path`. The 0.5.1 → 0.6.0 guide now installs the pinned `v0.6.0` tag, and the
  releasing guide documents the asset attachment.
- **PyPI is deliberately out of scope.** This repository has no trusted-publishing setup, so the
  release assets are the distribution channel. A follow-up can add a `pypi` job to the same workflow
  and publish the wheel and sdist it already builds; nothing in this release blocks that.

## Upgrade

Nothing to migrate: `spec_version` stays 6, every command, option, output and exit code is
unchanged, and ledgers open exactly as under 0.8.17. Reinstall with the pinned command above to get
the wheel that carries the skills; asset attachment starts with this release.

  merge; the command shape is identical).
