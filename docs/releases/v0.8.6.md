# 0.8.6 — `tm stock aliquot` positional sugar for `tm aliquot add`

`tm stock aliquot STOCK AMOUNT UNIT [--count N] [--status S] [--box NAME --slot S ...]` adds tubes
to an existing stock and names the amount of each one on the command line: it is exactly
`tm aliquot add STOCK --quantity AMOUNT --unit UNIT` with the same options. Both commands share one
implementation, so the human line, `--json`, the single Dolt commit and the exit codes are
identical. Additive: nothing breaks and nothing needs migrating.

## Positional amount, one write

```sh
tm stock aliquot 1226L501 50 ul --count 3 \
  --box WFL-12-02 --slot B1 --slot B2 --slot B3
# = tm aliquot add 1226L501 --quantity 50 --unit ul --count 3 ...
```

- `AMOUNT` is the quantity of **each** new tube, `UNIT` is its unit and `--count` still sets how
  many tubes to add. Both positionals are required; `AMOUNT` may be zero (core's non-negative rule
  stands) and `UNIT` keeps the core limits (non-empty, at most 32 characters).
- The command is pure CLI sugar: it and `tm aliquot add` call one shared helper that calls
  `ledger.aliquots.add(stock, quantity=AMOUNT, unit=UNIT, …)`. There is no new core or Python API.
- Same output as `tm aliquot add`: `Added N aliquot(s) to S: S.k, …`; `--json` returns
  `{object, stock_id, ids}`; the write is one commit, `add(aliquot): <stock_id> x<N>`.
- Same exit codes: 0 on success, 2 for a usage error (including a negative `AMOUNT`, which Click
  reads as an unknown option — there is no `--` escape), 1 for a ledger error and 3 when the ledger
  is unreachable.
- `tm stock --help` lists the command between `add-form` and `show`:
  `add, add-form, aliquot, show, list, edit, renumber, purge`.
- Use `tm stock aliquot` when every new tube has a known amount; `tm aliquot add` stays the form for
  tubes without a quantity.
- `tm aliquot add` is unchanged: same options, help and output.

## Upgrade

Nothing to migrate: `spec_version` stays 6 and the ledger format is unchanged. The command and the
0.8.6 release are additive; a ledger written by 0.8.4 opens unchanged.
