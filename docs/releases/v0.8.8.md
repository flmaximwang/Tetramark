# 0.8.8 — `aliquot_event.message` replaces `note` and `purpose`

Spec 7 ends the naming mismatch left by 0.8.0: `tm aliquot use` and `tm aliquot move` took
`-m/--message` but stored the text in `aliquot_event.note`, while the unused `purpose` column sat
next to it. One column now says what it holds. **This is a hard break for the ledger format and for
the event JSON/CSV keys** — a spec-6 ledger runs the new scripted migration; nothing else changes.

## The shape

`aliquot_event` goes from 16 columns to 15, and the event text column is renamed in place:

| before | after |
| --- | --- |
| `..., forced, actor, purpose, note, at` | `..., forced, actor, message, at` |

- `tm aliquot show --json` event records and `tm history --json` event rows carry `message`; the
  `purpose`/`note` keys are gone.
- `tm history --format csv` is **16 columns**, ending `..., forced, actor, commit_hash, message`.
  Event and commit rows share the last column: an event row fills `message` with the event text, a
  commit row with the commit message; `section` says which is which.
- `tm export`/`tm import` column sets and every preset are untouched: they referenced neither
  column.

## The guard is targeted

A spec-6 ledger still has the old columns, so the tool refuses it on exactly the paths that read or
write event rows — `record_event` (so `use`, `move`, `status` and an aliquot-creating `tm import`),
`show_aliquot`, and the event half of `history` — with an `LedgerError` that names the step:

```console
$ tm aliquot show 1226FP01.1
error: ledger is spec 6, tm is spec 7: aliquot_event still has the spec-6 columns (note, purpose).
Upgrade it with:
uv run migration/spec/6-to-7/migrate.py --ledger /path/to/ledger --apply
(dry run without --apply; see migration/spec/6-to-7/README.md)
```

`tm status`, `tm schema plan` and the list commands keep working on a spec-6 ledger and only show the
usual `ledger is spec 6, tm is spec 7` warning, so an operator can inspect a ledger before upgrading
it. A `tm check` still passes on the old format.

## The migration

`migration/spec/6-to-7/migrate.py` is the **only** step with a step-local `--apply` flag: without it
the command is a dry run, `--dry-run` is accepted identically, and only `--apply` writes. It creates
the `pre-migrate-spec-6` tag, then one commit, `migrate(ledger): spec 6 -> 7`:

- `RENAME COLUMN note TO message` — never copy-and-drop, so the column keeps its position;
- one `UPDATE` folds a non-empty `purpose` into the message: message empty → `message = purpose`;
  both non-empty → `message = purpose || '; ' || message`; values are copied verbatim, never
  trimmed. Both a dry run and an apply print `purpose folded into message: N row(s)`;
- `DROP COLUMN purpose`, then `MODIFY COLUMN message MEDIUMTEXT AFTER actor` when the two columns
  already had the target names.

The live column shape is read from `information_schema`, so hand-patched ledgers work too; the
ambiguous (`note` **and** `message`) and damaged (neither) shapes are refused **before** the tag, with
nothing written. The fold supersedes the spec 5 → 6 promise that past events stay untouched for this
one column; the original values remain in Dolt history at the tag.

## Upgrade

Run `migration/spec/5-to-6/README.md` first if the ledger is still spec 5, then:

```sh
uv run migration/spec/6-to-7/migrate.py --ledger /path/to/ledger            # dry run
uv run migration/spec/6-to-7/migrate.py --ledger /path/to/ledger --apply    # one commit
uv run tm -l /path/to/ledger check                                          # no FAIL
```

The full order, the column matrix, verification SQL and the rollback (`dolt reset --hard
pre-migrate-spec-6`) are in [`migration/spec/6-to-7/README.md`](../../migration/spec/6-to-7/README.md);
[`docs/guides/migrating-a-legacy-ledger.md`](../guides/migrating-a-legacy-ledger.md) has the
end-to-end upgrade path.

## Highlights

- `aliquot_event.message` is the one event-text column; `purpose` is dropped, `note` is renamed.
- `record_event` refuses a spec-6 ledger before the INSERT, so a refused write commits nothing.
- `tm history --format csv` is 16 columns; `purpose`/`note` are gone from the event JSON.
- The scripted 6 → 7 step is dry-run-by-default and refuses the ambiguous/damaged column shapes
  without writing a tag or a commit.
- `event_line` (the text rendering of an event in `tm history`/`tm aliquot show`) is deliberately
  unchanged: it still does not print the message; that is a separate follow-up.
- `tm aliquot status --note`/`ledger.aliquots.status(..., note=...)` still work (their value is stored
  in `message`); renaming that flag is `Tetramark-fga.2`, not this release.
