# 0.5.1 — full-word subcommands

Every abbreviated subcommand is now spelled out: `ls` becomes `list`, `rm` becomes `remove`. This is a
**hard break** — no compatibility aliases ship, so the old spellings are unknown commands and exit 2.
The change is **CLI-only**: ledgers, schema, presets and data are untouched (`spec_version` stays 5), so
nothing has to migrate.

## The rename

| 0.5.0 | 0.5.1 |
|---|---|
| `tm entity ls` | `tm entity list` |
| `tm stock ls` | `tm stock list` |
| `tm box ls` | `tm box list` |
| `tm branch ls` | `tm branch list` |
| `tm remote ls` | `tm remote list` |
| `tm alias rm` | `tm alias remove` |
| `tm remote rm` | `tm remote remove` |
| `tm backup ls` | `tm backup list` |
| `tm backup --ls` | `tm backup --list` |

## Highlights

- Subcommand names are full words from now on: `tm entity/stock/box/branch/remote list`,
  `tm alias/remote remove`, `tm backup list` and `tm backup --list`. The rule is stated in
  [`docs/spec/06-cli.md`](https://github.com/flmaximwang/Tetramark/blob/v0.5.1/docs/spec/06-cli.md) §6.
- `tm backup` is still a single command taking a positional directory, so a directory literally named
  `list` must be written `./list`. A bare `tm backup ls` is now a directory name, not the old listing
  sentinel — the upgrade note calls that out explicitly.
- Unchanged on purpose: the Python API (`Ledger.entities.ls()`, `Ledger.aliases.rm()`) and the Dolt
  commit verb `rm(alias)`. Those are library and ledger-data formats, not subcommands.
- The suite locks the rule in place: no command group may expose `ls`/`rm` (or any name shorter than
  three characters), and all eight 0.5.0 spellings must exit 2.

## Upgrade

See [`docs/guides/upgrading-0.5.0-to-0.5.1.md`](https://github.com/flmaximwang/Tetramark/blob/v0.5.1/docs/guides/upgrading-0.5.0-to-0.5.1.md):
the mapping table, the hard-break notice, a `grep`/`sed` recipe and a checklist. Scripts, shell aliases,
cron entries and Makefiles that still use an old spelling fail at their next run.
