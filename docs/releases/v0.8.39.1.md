# 0.8.39.1 — aliquot events say what happened and where

An event trail is only useful if it says what the person did. `tm aliquot show` and `tm history`
already printed the event type, amount, boxes, status and actor, but both dropped the stored
`aliquot_event.message`, and a box reference with no live box row printed as a bare UUID that was
indistinguishable from a box name. The shared event line now ends with the message as one quoted
JSON token and labels an unresolved reference as `[unresolved box <full id>]`; the JSON records add
two resolution flags. No ledger format changes: `spec_version` stays 7, nothing migrates, and the
16-column history CSV is untouched.

## What changed

- `tm aliquot show` and `tm history` render the same `event_line` grammar (spec `06-cli` §6.6). The
  stored message is the last token, `message="..."`, always double-quoted and JSON-escaped so the
  event stays exactly one physical line; CJK text remains literal.
- A place is the live box name plus its optional `:slot`. A box reference whose live row no longer
  exists prints `[unresolved box <full stored box id>]`, never a claim about deletion or any other
  cause. The complete id is kept so two different refs cannot be conflated.
- A renamed box shows its current live name in both commands. The old name stays an alias that
  `tm find` resolves; no name-at-event-time reconstruction or historical rewrite is attempted.
- `tm aliquot show --json`, `tm history --json`, `ledger.aliquots.show` and `ledger.history` gain
  additive `from_box_resolved`/`to_box_resolved` keys: `null` when the side has no box id, `true`
  for a live box row, `false` otherwise. `from_box`/`to_box` keep their old value (live name, else
  the stored id, `null` when the id is NULL).
- Box names for history are resolved by joins scoped to the matching events in the existing read
  batch; the unbounded all-box read is gone. Show keeps its single batch. No per-event SQL and no
  extra Dolt process or round trip.
- `tm history --format csv` keeps exactly 16 columns and the raw message; `tm aliquot show
  --format csv` still drops events.

## Compatibility

Additive only. Existing text lines gain the trailing message token and the unresolved-place form;
the JSON gains the two `*_box_resolved` keys and changes no other key. The 16-column history CSV is
byte-identical. `spec_version` stays 7.

## Upgrade

Nothing to migrate. No schema, preset or ledger-format change.
