# 0.8.42 — related objects in `tm stock show` and `tm aliquot show`

`tm stock show` now prints the objects its stock points at — its entity, its parent stock and its
source aliquot — and `tm aliquot show` prints the entity that owns the tube. The human output uses
plain `*` lines outside the rich tables; `--json` gains an additive `related` object; `--format csv`
is byte-for-byte unchanged. A deleted or unnamed reference no longer hides the rest of the record:
each is labelled in place, and a missing related object never fails an otherwise successful show.

## Related-object lines

Text output prints one line per related object, starting at column zero with `* ` and the label
padded to a 14-character column so every value starts at column 18:

```text
* entity          plasmid · pUC19
* parent stock    bacterial_glycerol · 745b8daa (pUC19)
* source aliquot  0826FP01.1 · stored · bacterial_glycerol of pUC19
```

`tm stock show` prints the lines between the stock's field block and `aliquots  N` (then the tube
cards, as before), in the order entity, parent stock, source aliquot. `tm aliquot show` prints its
`* entity` line after the field block and before the optional `path:` line and the events section.
UUID ids use the same eight-character prefixes as the list output; aliquot ids stay full
`<stock>.<seq>` values. A NULL optional reference prints no line.

The missing-data labels are exact:

- An existing entity with no name prints `kind · <short id> (unnamed)`; a deleted one prints
  `<short id> (missing)`.
- A parent stock prints `kind · <short id> (<its entity>)`, where the entity part is the name,
  `unnamed entity <short id>` or `missing entity <short id>`; a deleted parent prints
  `<short id> (missing)`.
- A source aliquot prints `<full id> · <status> · <kind> of <entity>`, with the same `of unnamed
  entity …` / `of missing entity …` endings; a deleted source prints `<full id> (missing)`.

Parent and source lines resolve their **own** entity, never the displayed stock's. Actual control
characters in these lines (newline, carriage return, tab) become the literal separator ` | `, not
backslash escapes; ordinary text is untouched.

## JSON and CSV

`tm stock show --json` adds `related`:

```json
{
  "related": {
    "entity": {"id": "…", "kind": "plasmid", "name": "pUC19"},
    "parent_stock": {
      "id": "…", "kind": "bacterial_glycerol",
      "entity_id": "…", "entity_name": "pUC19", "entity_missing": false
    },
    "source_aliquot": {
      "id": "….1", "seq": 1, "status": "stored", "stock_kind": "bacterial_glycerol",
      "entity_id": "…", "entity_name": "pUC19", "entity_missing": false
    }
  }
}
```

`tm aliquot show --json` adds `related.entity` with the same `{id, kind, name}` shape. A NULL
reference is `null`; a deleted object is `{"id": "…", "missing": true}`; an existing entity with no
name has `name: null` (or, inside a parent/source, `entity_name: null` with `entity_missing:
false`), and only that part is marked missing.

`--format csv` keeps exactly the columns it had before: it drops `related` (and, for `aliquot
show`, `events` as before) and adds no columns or lines. Existing JSON keys are retained, including
`entity_id` and `stock_kind` on the aliquot record and the enriched tube rows on the stock record.
The lookups are bounded: `stock show` resolves all three relations as extra statements inside the
stock's own read batch (no extra process, no growth with the tube count), and `aliquot show`
resolves its entity in the query it already runs. `tm aliquot list --json` keeps its old shape: a
list row is the show record without `events` and without `related`.

## Highlights

- `tm stock show`: field block → `* entity` → `* parent stock` → `* source aliquot` → `aliquots  N`
  → cards. CSV and the tabular card layout are otherwise untouched.
- `tm aliquot show`: field block → `* entity` → `path:` → `events  N` and event lines. JSON adds
  `related` and keeps every existing key.
- Missing references print `(missing)` with their id and exit 0; wrong object types keep the
  not-found error that names the other verb (`tm aliquot show <stock>` → try `tm stock show`).
- Spec §6 and `references/commands.md` describe the shipped behaviour; the "planned" section is
  gone. Both `SKILL.md` files are re-stamped to 0.8.42.

## Upgrade

Nothing to migrate: no schema, DDL, preset, migration step or ledger format changed, and
`spec_version` stays 7. A positional CSV consumer sees the same columns; a JSON consumer sees the
additive `related` object and may ignore it.
