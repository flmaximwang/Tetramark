# 0.8.56 — confirmed aliquot use, audited reversals (spec 9), and `tm find` reads event messages

Two merges landed on `main` after 0.8.55 without a version bump, so neither was released. This one
carries both: **spec 9** makes `tm aliquot use` a confirmed, reversible action with a `revert_use`
audit event, and **`tm find`** now searches `aliquot_event.message` and filters aliquots instead of
silently leaving them out of every filtered search. It also finishes two documentation nits 0.8.55's
merge left behind: the `--yes` flag was missing from the `tm aliquot use` signature, and the skill's
decision table still described the pre-0.8.55 `use` line.

**Ledgers at spec 8 need the manual 8 → 9 step** (`migration/spec/8-to-9/README.md`); ledgers at
spec 9 or created by `tm init` need nothing. No preset changes, no column is rewritten, existing event
rows and IDs are preserved.

## `tm aliquot use` confirms before it deducts

```text
tm aliquot use ALQ [AMOUNT UNIT] -m MSG [--yes]
tm aliquot use ALQ --revert-last -m MSG [--yes]
```

- **One preview, one question.** The command validates, prints the canonical id, the operation, the
  reason, the quantity before and after and any status/placement change to **stderr**, and asks
  `Confirm? [y/N]` exactly once. Enter, `n`, or end-of-input cancels with `Cancelled` on stderr and a
  nonzero exit, writing no row, no event and no commit.
- **`--yes` for scripts and agents.** A real write with non-interactive stdin and no `--yes` exits
  nonzero with `tm aliquot use requires confirmation; pass --yes in non-interactive mode`.
  `--dry-run` validates and previews without prompting and writes nothing, with or without `--yes`;
  `--no-commit` still confirms a real write and leaves the row and the event together in the working
  set.
- **The state is revalidated under the write lock**, after the prompt: if the target or the relevant
  state changed while waiting, the write aborts and asks the caller to rerun the command. A `--yes`
  never applies to a different use than the one previewed.
- **`--json` keeps stdout for the result**; the preview, the prompt and the cancellation line all go
  to stderr.

## `--revert-last` undoes the latest use, and records that it did

- It selects the **most recent original `use`** on the resolved branch, refuses when there is none or
  when that one already has a reversal (repeated invocations never step back to an earlier use), and
  refuses when a **later change to quantity, unit, status or placement** followed it. A label or alias
  change does not block the revert and is preserved.
- It restores the pre-use **quantity, unit, status and placement**: a partial deduction restores the
  amount consumed; a whole-tube deduction restores the prior quantity and status plus the box and slot
  it cleared. A quantity that was unknown stays unknown — the command never guesses a historical
  value or status, and missing or ambiguous evidence is an error. Historical `use` rows that predate
  spec 9 are eligible once the ledger is upgraded.
- The result is validated as a real row before anything is written: a former slot that no longer
  exists, accepts no tube, or is now occupied aborts the whole operation, and the occupied case names
  the occupant. Retry once the position is free.
- The reversal is a **new event of kind `revert_use`** in the same transaction as the row update: it
  names the exact original `use` in `aliquot_event.reverts_event_id`, keeps the operator's reason,
  actor and timestamp, and records the restored amount and the status/placement it changed. The
  original row is never touched, so the audit shows both the deduction and the correction. One
  successfully applied reversal is one Dolt commit.
- `tm history` and `tm aliquot show` show the reversal and the use it points at, in text and in JSON
  (`id` and `reverts_event_id` tokens; the event object carries both).
- `tm check` recognizes a correction that restores an old status, and the generated
  `core_revert_event_allowed` / `core_revert_event_unique` tests catch invalid manual changes.

## Spec 9: the schema step

`migration/spec/8-to-9/` is scripted (`migrate.py`) and its README is the operator's contract. On
`aliquot_event` it appends `revert_use` last in the `event` ENUM (every stored value keeps its index),
adds a nullable `reverts_event_id BIGINT AFTER event`, and installs three constraints:

| constraint | what it enforces |
| --- | --- |
| `uq_aliquot_event_reverts_event_id` | a `use` is reversed at most once — including two concurrent attempts, where the loser gets a duplicate-key error |
| `ck_aliquot_event_reverts_event_id` | the reference is present exactly on `revert_use` rows |
| `fk_aliquot_event_reverts_event_id` | the target row exists; deleting the original `use` (as `aliquot purge` does) takes its reversal with it |

`record_event` checks inside the writing transaction that the target is a `use` on the same aliquot.
No other table, no `ledger_meta` key and no preset moves, and `ledger_meta.spec_version` becomes 9.

## `tm find` searches event messages, and reads aliquots under a filter

- **`aliquot_event.message` is a search place**: the stored raw text, not the rendered
  `message="…"` event line. It ranks in the field tier — exact and substring, case-insensitively, no
  prefix sub-tier — and takes part in `-E`, where one ICU regex spans every place including event
  messages. A tube is one hit however many of its events match, and the hit names the tube, not the
  event.
- **`--where` / `--where-any` now read aliquots** over their filterable columns (`id`, `stock_id`,
  `seq`, `box_id`, `slot`, `status`, `quantity`, `unit`, `label`, `created_at`, `stock_notes`) instead
  of excluding them whenever either group was given. A field they lack (`kind`, `batch`, `resistance`,
  …) excludes them exactly as it excludes a kind that does not declare it: `tm find 1226L401.1
  --where 'id~^12'` now matches, `tm find 1226L401.1 --where 'kind~.'` still reports no match. `status`
  is accepted here because `tm find` has no `--status` option.
- The find query path calls `require_spec7_event_columns`, so a spec-6 ledger gets the targeted
  "this ledger needs the 6 → 7 step" notice rather than a raw SQL error about the `message` column.

  returned nothing for the filtered form.

## Upgrade

- **Spec 8 ledgers**: run the 8 → 9 step in `migration/spec/8-to-9/README.md` (tag `pre-migrate-spec-8`,
  run `migrate.py`, then `tm check`). `--revert-last` on an un-upgraded ledger reports the upgrade
  requirement before writing; every other command keeps working.
- **Spec 9 ledgers and fresh `tm init` ledgers**: nothing to migrate.
- **Scripts that call `tm aliquot use`**: they need `--yes` now. This is the one hard break in this
  release; a non-interactive `use` without it exits nonzero instead of deducting.
- No preset change, no CLI command renamed, no documented output shape removed. `tm find` gains hits it
  did not report before — a search that previously found nothing may now find tubes.
