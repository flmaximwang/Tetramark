# 0.8.43 — Dolt workload reduction in the test suite

0.8.43 is a **test-harness release**. It changes `tests/conftest.py`, the expensive module fixtures,
the test-harness guide, the version files and these notes. Nothing in `src/` changes except the
`__version__` stamp, the shipped skills change only in their version stamps, and nothing in the CLI,
the Python API, the ledger format or the skill content changes: `spec_version` stays 7, and no schema, DDL, preset or migration step moves. The **30 s
fast-lane budget, 300 s full-suite budget and 60 s per-test timeout are unchanged**, as are every
existing test, assertion and timeout exception.

## Shared closed builds

A module-scoped fixture is rebuilt once per pytest **worker**, and under `--dist worksteal` one
module's tests can be spread over several workers, so a 20–25 s build was paid again per worker.
`tests/conftest.py` now has a `SharedBuilds` helper that applies the existing ledger-template
protocol to any directory-shaped fixture:

- the first caller builds once per session under an exclusive `flock`, into a temporary sibling;
- the complete directory is published with one atomic `os.rename`, and only then is `<key>.ready`
  written — an interrupted publisher, including the crash window where the rename happened but the
  marker did not, is discarded and rebuilt;
- the published directory is **closed** (no cached `dolt sql-server`, no discovery file pointing at
  a live port) and carries the builder's original IDs and expected-value metadata as JSON inside the
  same directory, so a worker can never see a ledger and metadata from different builds;
- each worker copies the closed directory and reopens its own copy, so no live `Ledger` or server is
  shared across workers;
- a builder `pytest.skip` still reaches every caller with the same message and is never cached.

This covers the populated round-trip ledgers (`test_list_round_trips.py`, `test_csv_round_trips.py`,
`test_lineage_round_trips.py`) and the migration builders (`rebuilt_molbio_v1`,
`rebuilt_spec4_boxes`). The migration builders still execute their pinned legacy code and original
checks inside the session clock; only the duplicate per-worker builds disappear.

## Concurrency

The suite's time is dominated by waiting on `dolt sql` subprocesses and `dolt sql-server` round
trips, not by Python CPU. At the former `-n auto` (10 workers on the 10-core reference host) only
about 2.4 cores were busy while the full suite ran, so the default is now **`-n 16`** with the same
`--dist worksteal`: the same 1997 tests, the same 30/300/60 s limits and the same assertions, with
more of those waits overlapped. Measured idle on the reference host: **273.7 s at 10 workers,
265 s at 14 and 253 s at 16**; twenty workers reached ~250 s but pushed the pinned migration
drift-guard test past its unchanged 60 s timeout, which is why 16 is the settled value. The test
count, markers, timeouts, skip set and budget clock are unchanged — this is a scheduling change,
not an exemption, and a budget breach still fails the run.

The no-op `xdist_group("form_dolt")` mark is removed: `pytest-xdist` ignores grouping under the
configured `--dist worksteal`. Those form parity tests stay embedded with the same assertions and
timeouts.

## Measurements

Measured on the reference machine (10-core macOS, `-n 16 --dist worksteal`) on 2026-11-07,
comparing clean base `87958e9` with the change tree based on it:

- Fixture-setup/build counts across workers: `source` 3→1, `exported` 3→1, `template` 3→1,
  `read_ledger` 2→1, `rebuilt_molbio_v1` 1→1, `rebuilt_spec4_boxes` 1→1 — **13 → 6** in total.
- Exactly one real shared build per key per session: `list-round-trips`, `csv-round-trips`,
  `lineage-round-trips`, `rebuilt-molbio-v1` and `rebuilt-spec4-boxes` each report `builds=1`.
- Dolt workload: **660 `dolt sql-server` starts** and **0 owned leftover servers** in the full runs.
- Idle full suite: **273.68 s internal at the former 10 workers → 253.05 s internal (253 s wall) at
  `-n 16`**, 1995 passed and 2 optional skips.
- Fast lane: **12.8 s, 1009 passed**, inside the 30 s budget (the fast lane prefers fewer workers; 16 adds a few seconds of xdist overhead there but the full suite gains ~20 s).
- A first merger gate on the previous head measured 342.69 s while another merger gate was running
  on the same host (its fast lane took 17.01 s against ~8 s here, and its total CPU was unchanged);
  the failure was that concurrent-suite contention, not extra work. The gates on the quiet host
  and on the committed head are recorded in the ticket and PR.

## Verification

- Collect-only coverage equivalence: **1989 base nodes → 1997 final nodes, 0 missing**, and the 8
  additions are exactly `tests/test_shared_builds.py`. The `embedded` marker set is **167 == 167**
  and the `embedded_driver` set **102 == 102**, with identical membership; no test, timeout,
  `xfail`, skip or deselect changed.
- The final sequential gates on the committed head (fast lane ≤ 30 s, full suite ≤ 300 s with no
  test over 60 s, `python3 scripts/release_check.py` ready, 0 owned leftover `dolt sql-server`)
  are run by the verifier/lead and recorded in the ticket and PR.
- `-n 16` was chosen by measurement: 10/273.7 s, 14/265 s, 16/253 s, 20/250 s but a 60 s timeout in
  the pinned migration drift-guard test. Budgets and per-test timeouts are unchanged.

## Upgrade

Nothing to migrate: no product behaviour, CLI, Python API, schema, preset, migration step or ledger
format changed. `spec_version` stays 7, and any ledger written by an earlier release opens
unchanged. The suite's acceptance limits are exactly the same as before.
