# 0.8.44 — the suite-budget regression is deterministic

The wall-clock guard that fails an over-budget test session now has a deterministic regression
test. The previous test proved the guard counts the *whole* session finish by sleeping five real
seconds in an inner pytest session's `sessionfinish`; under load that inner run could exceed the
test's own 110 s subprocess ceiling and the test went red for a reason that had nothing to do with
the behaviour it names (GitHub issue #68 territory, re-raised by Tetramark-0d7).

Nothing about the guard, the budgets or the product changed: the real clock is still
`time.monotonic`, the budgets are still 30 s (fast lane), 300 s (full lane) and 60 s per test, and
`TETRAMARK_SUITE_BUDGET_SECONDS` still overrides or disables them. This release changes only the
test harness and its documentation.

## The clock seam

`tests/conftest.py` now measures the session with a module attribute:

```python
_suite_clock: Callable[[], float] = time.monotonic
```

`pytest_configure` stamps `_SUITE_STARTED = _suite_clock()` and the `trylast`
`pytest_sessionfinish` computes `elapsed = _suite_clock() - _SUITE_STARTED`. The default is the
real monotonic clock, so production behaviour is byte-for-byte the same as before.

A test replaces **that attribute**, never the global `time.monotonic` or `time.sleep`: pytest,
xdist, PyMySQL and the Dolt supervision code all read real time, and patching the globals would
reach them too.

## The regression and its negative control

`tests/test_suite_budget.py` runs a tiny inner pytest session with a 3 s fast-lane budget and an
injected fake clock, and asserts the exact banner:

```text
SUITE TIME BUDGET EXCEEDED: 5.0s > 3s
```

The elapsed time is the fake clock's, so a loaded machine cannot turn the test red; the inner
session no longer costs five seconds of wall clock either (the focused file runs in about one
second instead of twelve).

The ordering is pinned from both sides:

- the **positive** test advances the fake clock in a plain plugin `sessionfinish`. A `-p` plugin is
  registered before `tests/conftest.py`, so pluggy calls its hook after an unmarked conftest hook —
  exactly like pytest's own tmp_path plugin, whose cleanup deletes old `pytest-N` directories full
  of Dolt ledgers. The guard is `trylast`, so it runs after that hook and sees the advanced clock;
  the session must fail;
- the **negative control** advances the same clock in a `hookwrapper`, whose post-yield code runs
  after every non-wrapper implementation — after the guard has measured the session. The session
  must stay green.

Dropping `trylast` from the guard turns the positive test red and leaves the negative control
green, so the pair discriminates the ordering instead of asserting a constant.

## Unchanged on purpose

- the over-budget test, the disabled-guard test, the inner `-n 0`, the `-p no:cacheprovider` flag
  and the 110 s / 120 s subprocess ceilings are unchanged: the ceilings remain a guard against a
  hung child;
- the 30 s / 300 s / 60 s budgets and the environment override are unchanged;
- no product code, schema, `spec_version` or CLI behaviour changed — the only `src/` edit is the
  version stamp.
