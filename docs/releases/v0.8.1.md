# 0.8.1 — wrapping stock cards, regex find and rewrite rules

`tm stock show` now draws one card per aliquot and flows the cards in rows; `tm find` and the three listings share one filter syntax with regex support; and a ledger can declare `find.rewrites` rules that rescue literal searches with zero hits. Nothing breaks and nothing needs migrating.

## Stock show cards

`tm stock show` keeps the stock's field block, then prints `aliquots  N` and one **card per tube**:

```
aliquots  2
╭─ 1226L401.1 · stored ─╮ ╭─ 1226L401.2 · pending ─╮
│ 500.000000 ul         │ │ no quantity            │
│ label: first tube     │ │ not in stock           │
│ WFL-12-01:A1          │ ╰────────────────────────╯
│ aliases: tube-A       │
╰───────────────────────╯
```

- The title is `<id> · <status>` (status colour); then the quantity/unit, a `label:` line when set, the slot-inclusive path (or `not in stock`), and an `aliases:` line when set.
- Cards flow left to right and wrap at the console width; a narrow terminal stacks them.
- The embedded rows gain `label`, `box_id`, `slot`, `path`, `aliases` and `in_stock` (additive for `--json`). `--format csv` is unchanged, and `tm aliquot list STOCK` remains the tabular tube view.
- The rows, paths and aliases ride in the existing `show_stock` batch: no per-tube query.

## Filters and regex find

- `tm entity list`, `tm stock list`, `tm box list` and `tm find` share one repeatable `--where` syntax: `field=value` (exact, schema-coerced) or `field~pattern` (regex). Rules: one `=` per field, any number of `~` (ANDed); an unknown field, an empty pattern or an invalid regex is a usage error (exit 2).
- `~` matches the column's text form with a Dolt ICU regex: a case-sensitive search, `(?i)` for case-insensitive; `NULL` never matches.
- `tm find -E/--regex` makes QUERY a case-insensitive ICU regex over ids, aliases, names and `string`/`text` kind fields. `tm find --where ...` without a query lists every match; no match exits 1.
- Python: `where=` takes a mapping (equality only) or a list of filter strings. Listings and `find` read in one batch.

## `find.rewrites` rules

A ledger may declare rewrite rules for literal `tm find` queries in `ledger.yaml`:

```yaml
find:
  rewrites:
    - name: type-code
      pattern: '^05(\d{2})-(.+)$'
      replacement: '05PR\1-\2-FL1'
```

- Each rule has a unique `name`, a Python `re` `pattern` matched against the whole trimmed query, and a `replacement` expanded with back-references. The rules are validated when the ledger opens (bad pattern, bad group reference, missing/duplicate name, empty list).
- By default they are a **zero-hit fallback**: a literal query with hits is searched normally; only a zero-hit query tries the rules, in order, and shows the first rule's hits with a stderr hint (`no match for 'X'; showing matches for 'Y' (rule 'NAME')`).
- `--with-rewrite` runs every rule in addition to the original query on every literal search; original hits rank above rewrite hits, rewrite hits read `<tier> via <rule>` and carry `"rewrite": {"rule": ..., "query": ...}` in JSON.
- Rewrites apply to literal `QUERY` only: `-E` and `--where` are never rewritten, and single-object resolution (`show`, `history`, `lineage`) stays exact.
- A ledger that carries `find:` needs tm 0.8.1 or newer: older releases refuse the unknown key.
