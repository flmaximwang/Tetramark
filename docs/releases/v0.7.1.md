# 0.7.1 — `tm aliquot show`: read one tube

`tm aliquot show ALQ` reads one tube: its status, quantity, unit and label, the stock and entity it
belongs to, and where it sits in the freezer (`WFL-12-01:A1`). An aliquot had only write verbs
(add, move, use, status, purge) until now, so reading one tube meant combining `tm find`,
`tm history` and `tm stock show` — and `tm stock show`'s aliquot rows carried neither the label, nor
the aliases, nor the box path.

CLI-only: no ledger format change (`spec_version` stays 5), nothing to migrate.

## The new verb

```sh
tm aliquot show 1226L401.1
```

```
id          1226L401.1
stock_id    1226L401
seq         1
status      stored
quantity    500.000000
unit        ul
label
notes
created_at  2026-11-04 13:15:32
aliases
stock_kind  bacterial_glycerol
entity_id   2103f587
box_id      c04c4af8
slot        A1
in_stock    true
path: WFL-12-01:A1
```

- `ALQ` is the full `<stock>.<seq>` id or one of the tube's aliases — including the old ids
  `tm stock renumber` keeps. An aliquot id is never shortened.
- The record holds the aliquot row, the sorted `aliases`, the owning stock's `stock_kind` and
  `entity_id`, the `box_id`/`slot`, the `path` down the box nesting and the derived `in_stock`
  flag (the tube's status has `in_stock: true` in its stock kind's status set).
- A tube that is not in stock carries no position: `box_id`, `slot` and `path` are empty (`null` in
  JSON) and `in_stock` is false.
- `--json` prints the same record with the full ids; the global `--json` / `--format` flags work as
  everywhere else, and the text output shortens uuid ids the way the list commands do.
- The stock kind's own fields stay in `tm stock show`, and the tube's events stay in
  `tm history ALQ`: `show` carries no event timeline.

## Wrong-type hints

Reaching for the wrong verb now names the right one:

```console
$ tm aliquot show 1226L401
Error: unknown aliquot '1226L401': 1226L401 is a stock; try tm stock show 1226L401

$ tm stock show 1226L401.1
Error: unknown stock '1226L401.1': 1226L401.1 is an aliquot; try tm aliquot show 1226L401.1
```

Both are the ordinary not-found error (exit 1, `Error:` on stderr); a ref that names nothing keeps
the plain message.

## Python API

`ledger.aliquots.show(ref)` mirrors `ledger.stocks.show(ref)` and returns the same record.

## Upgrade

Nothing to migrate. A 0.7.0 ledger opens unchanged under 0.7.1; `spec_version` stays 5.
