# 0.6.1 — find matches part of an alias

`tm find` now matches aliases by prefix and substring as well as by the whole
string, so a lab alias such as `6xHis-gammaPFD-HisProbe-1.3` is reachable with
`tm find gammaPFD`. It is a **CLI read-side** release: ledgers, schema, presets
and data are untouched (`spec_version` stays 5), so nothing has to migrate.

## Ranking

An alias hit now has two tiers of its own, and an exact id or exact alias still
wins over every partial match, so the first hit for a precise query does not
change:

| Match | Score | Example |
|---|---|---|
| exact id | 1000 | `tm find 6c92b217-…` |
| exact alias | 900 | `tm find 6xHis-gammaPFD-HisProbe-1.3` |
| exact name | 800 | `tm find pZET043-gammaPFD_wt` |
| name prefix | 700 | `tm find pZET043` |
| **alias prefix** | **690** | `tm find 6xHis-gamma` |
| name substring | 600 | `tm find gammaPFD` |
| **alias substring** | **590** | `tm find gammaPFD` |
| field exact / substring | 500 / 400 | `tm find pZET043` |

The `match` column in table/JSON output still names the winning tier, so an
alias hit (`alias`) stays distinguishable from a name hit (`name`).

## Highlights

- Alias matching is literal and case-insensitive, like every other `find`
  tier: `%` and `_` are ordinary characters.
- Exact id and exact alias keep their precedence, so a script that uses a
  complete id or alias gets the same first hit as before.
- A short query may return **more** rows: a substring of an alias is now a
  hit. Use the full id/alias when a single row is required.
- No new command, flag, config key or schema field; no preset version bump, no
  migration step.

## Upgrade

Nothing to migrate. `tm find` is read-only and the ledger format does not
change; a 0.6.0 ledger opens unchanged under 0.6.1.
