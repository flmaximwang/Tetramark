# 0.8.23 — `tm aliquot list --where FIELD=` finds the empty fields

`tm aliquot list --where box_id=`, `label=` and the other aliquot core columns now read an
exact filter whose value is exactly the empty string as "the field is empty", matching the
meaning 0.8.22 gave `tm entity list`, `tm stock list`, `tm box list` and `tm find --where`. A
text-like column (`id`, `stock_id`, `box_id`, `slot`, `unit`, `label`, `notes`) matches when it
is `NULL` or `''`; `seq`, `quantity` and `created_at` match `NULL` only, so a stored `quantity`
of `0` never looks empty. Before this release the filter always compared the column against
`''`: `NULL` never matched, and a stored `0` was the only row `quantity=` could select.

The Python mapping form is fixed too: `ledger.aliquots.ls(where={"field": None})` used to
stringify `None` to the literal text `"None"` and match only that text. `None` now means the
empty value, exactly like `{"field": ""}` and the list form `["field="]`. Callers that relied
on `None` matching the literal text `"None"` must pass the string `"None"`.

## What changed

- **`tm aliquot list --where field=` means "the field is empty".** Text-like core columns
  (`id`, `stock_id`, `box_id`, `slot`, `unit`, `label`, `notes`) match
  `(<column> IS NULL OR <column> = '')`; `seq`, `quantity` and `created_at` match
  `<column> IS NULL` only. The condition carries no SQL parameter.
- **`quantity=` never selects a stored `0`.** The DECIMAL column is not compared through a
  string, so the empty filter cannot pick up a zero quantity; it selects the tubes whose
  quantity is unknown (`NULL`).
- **The Python mapping accepts `None` and `""`.** `where={"field": None}`,
  `where={"field": ""}` and `where=["field="]` are the same filter inside
  `ledger.aliquots.ls`.
- **Nothing else changed.** `status=` is still the `--status` usage error, an unknown field
  still lists the valid ones, whitespace-only values (`--where 'label=  '`) and the literals
  `none`/`null` stay exact matches, a non-empty `field=value` still compares with `= %s`, and
  the `field=value` parser used by `tm aliquot set` is untouched (this filter has its own
  parser). The default in-stock scope is unchanged: an unplaced tube is `pending`, so `--all`
  or an explicit `--status` is still what shows it.

## Upgrade

Nothing to migrate: `spec_version` stays 6 and the ledger format is unchanged. A ledger
written by any 0.8.x release opens unchanged. Only the meaning of an empty aliquot filter
value and of a `None` mapping value changed; both are described above.
