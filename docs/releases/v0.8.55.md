# 0.8.55 — tm parent/tm child: read, set and clear the relation between two objects

Until this release, parent/child relations were reachable only in narrow ways: `parent_stock_id`
and `source_aliquot_id` could be set only at creation (`tm stock add --parent`/`--source-aliquot`),
`tm stock edit` accepted only notes plus kind fields, a box parent changed only through
`tm box move`, and `tm lineage` was read-only. Re-parenting an existing stock — the original case,
a `bacterial_pellet` — meant a lossy purge plus re-add, and raw SQL was out of bounds. This release
adds the general, object-agnostic pair of commands the wave was opened for (**Tetramark-ka8**,
implementation ticket **Tetramark-ka8.1**).

## What is new

- **`tm parent REF_A [REF_B] [--set] [--clear] [--via FIELD] [--slot S]`** and
  **`tm child REF_B [REF_A] [--set] [--via FIELD] [--slot S]`**, in the Inventory help panel
  immediately after `box`. `tm parent A B` reads "the parent of A is B"; `tm child B A` names the
  same pair inversely, and `tm child B A --set` is the same write as `tm parent A B --set`.
- **A bare call reads, every write is explicit.** One ref lists that object's parent relations
  (`tm parent A`) or child relations (`tm child B`); two refs report the relation between the two
  objects and exit 1 when there is none; `--set` writes and `tm parent A --clear` removes. There is
  no `tm child --clear` (removal is `tm parent <CHILD> --clear`).
- **Every in-scope edge is an existing column**: `stock.parent_stock_id`,
  `stock.source_aliquot_id`, `box.parent_box_id` (+ `box.parent_slot` via `--slot`) and a kind's
  `type: ref` field. No table, column or migration is added, and `spec_version` stays unchanged.
- **One selector for ambiguous pairs.** A pair with one legal field is inferred; a pair with
  several (for example `mouse_cohort` → `aliquot`, which offers `dam`, `sire` and `source_aliquot`)
  is a usage error that lists the candidates and requires `--via FIELD`. `--via` takes the bare
  field name, and it is the only path to a `type: ref` field without `lineage: true`.
- **`ledger.relations`**: `get_parent`, `get_children`, `get_relation`, `set_parent`,
  `clear_parent` and `clear_relation`; the CLI is a thin layer over them and the return objects are
  the `--json` shapes.

## Behaviour worth knowing

- **Cycles are refused** before anything is written: box containment (a box never nests in itself
  or a descendant), the stock graph over `parent_stock_id` **and** `source_aliquot_id` together (the
  edges `tm lineage` walks), a self-parent, and a kind ref field along that same field. The error
  names the offending ids and nothing is committed.
- **Overwriting is silent**, like `tm box move`; the text and `--json` output report both the
  previous and the new parent. Re-parenting keeps the object's id and aliases, so the purge plus
  re-add workaround is no longer needed. One write = one write lock + exactly one Dolt commit
  (`parent(<object>): <child> <field> -> <parent>`).
- **`--dry-run` and `--no-commit` both preview the intended SQL and write nothing** for these two
  commands, for `--set` and `--clear`: no row change, clean working set, no commit, no write lock.
  This is specific to `tm parent`/`tm child`; every other command keeps the global `--no-commit`
  meaning ("execute, do not commit"), and its tests are unchanged.
- `--json` on a read prints `{"relations": [...]}`; on a write it carries `action`, `via`, `child`,
  `parent`, `previous` and, for a box parent, `slot`/`previous_slot`.

## Deliberately out of scope, and deferred

- `aliquot → box` placement stays with `tm aliquot move` (irreversible, requires `-m`, writes an
  event row); `stock.entity_id` re-binding is a separate ticket; identity/scalar fields, box names
  and edges with no existing column stay with their own commands or would need a dedicated relation
  table.
- No same-entity rule is enforced (a stock's parent may belong to another entity, exactly as
  `tm stock add --parent` already allowed), and the ledger-local rules **L02**/**L03** are not
  checked at write time: run `tm check`. Both are recorded as `TODO(Tetramark-ka8)`.

**No schema change, no migration, `spec_version` unchanged.** The settled specification is in
`docs/spec/06-cli.md` §6.7 (the matrix, selector, errors, flags and Python API), with cross
references from the edit, `tm aliquot move`, `tm lineage` and Python-API passages.
