# 0.8.0 — one fixed status set, and use/move carry a message

Every aliquot now has one fixed, hardcoded status — `pending`, `stored`, `missing`, `consumed` — that
every stock kind shares; presets no longer declare a status vocabulary at all. In the same release,
`tm aliquot use` and `tm aliquot move` require `-m/--message`, and `use` consumes directly (optional
`AMOUNT UNIT`, no `--purpose`/`--note`). Both are **breaking**. A spec-5 ledger still opens, but
moving it to spec 6 is a **manual, documented** upgrade: there is no `migrate.py` for it.

## What breaks

| Break | What to do |
|---|---|
| `tm aliquot use` no longer takes `--purpose` / `--note` (removed outright, no aliases) | pass `-m/--message` |
| `tm aliquot use` and `tm aliquot move` require `-m/--message`; a missing option is a usage error (exit 2) | add `-m "why"` to every call |
| `tm aliquot use` now consumes directly: reaching zero sets `consumed` and clears the box slot | read the new line/JSON (`used_amount`, `used_unit`, `message`) |
| A preset that declares `status_sets:` or a stock kind's `statuses:` is a **load error** | replace the ledger's preset closure (manual step below) |
| `aliquot.status` carries a real DB `CHECK (status IN ('pending','stored','missing','consumed'))` | remap old status words first (map below) |
| The generated `core_aliquot_status_known` test is gone; one global `core_status_event_allowed` replaces it | `tm schema apply` regenerates the tests |
| 13 bundled presets bumped; `thawed` is now `consumed` | copy the new preset versions, or follow the migration README |
| Python API: `ledger.aliquots.use(ref, amount=None, unit=None, *, message)` and `move(..., message)` | add the keyword argument |

`spec_version` is **6**. A spec-5 ledger keeps opening and `tm check` keeps running *its* stored
presets (an old ledger stays green); `tm` prints
`ledger is spec 5, tm is spec 6: follow migration/spec/5-to-6/README.md to upgrade it manually`.

## The fixed status set

| status | meaning | `in_stock` | allowed transitions |
|---|---|---|---|
| `pending` | ordered or planned; not physically here yet | no | `stored`, `missing`, `consumed` |
| `stored` | physically here and usable | yes | `missing`, `consumed` |
| `missing` | cannot be found now; may come back | no | `stored`, `consumed` |
| `consumed` | gone for good; final | no | none |

`stored` is the only in-stock status, for every kind: the stock views count an aliquot in stock
exactly when its status is `stored`, and `tm aliquot list` with no filter prints those tubes.
Creating an aliquot (`tm stock add`, `tm aliquot add`, `tm import`) accepts any of the four; changing
one (`tm aliquot status`) must follow the table. An unforced event that breaks a transition fails
`tm check`.

The old per-kind vocabularies (`tube`, `cryo`, `animal`, `fly`, `worm`) map to the fixed set; a word
that already has a fixed-set name keeps it.

| old status | new status |
|---|---|
| `planned` | `pending` |
| `alive`, `crossed`, `growing`, `starved` | `stored` |
| `lost` | `missing` |
| `thawed`, `euthanized`, `found_dead`, `transferred`, `cancelled`, `discarded`, `contaminated` | `consumed` |

`thawed` means the same as `consumed`: a thawed cryo vial is gone. A cryo vial is `stored` in the
freezer and `missing` or `consumed` after it leaves; there is no separate cryo vocabulary any more.
The detailed states those words carried are stock properties or event messages now, not statuses.

## Use and move carry a message

An action in the physical world that cannot simply be reversed needs a message (spec §1). Today that
is `use` and `move`.

```sh
tm aliquot use ALQ [AMOUNT UNIT] -m MSG
tm aliquot move ALQ --box NAME [--slot S] [--status S] -m MSG
```

```
$ tm aliquot use 8826L401.1 50 ml -m "ran the first assay"
Used 50 ml from 8826L401.1 (stored, 150 ml left): ran the first assay

$ tm aliquot use 8826L401.1 50 ml -m "second assay" --json
{
  "id": "8826L401.1",
  "message": "second assay",
  "object": "aliquot",
  "quantity": "100.000000",
  "status": "stored",
  "unit": "ml",
  "used_amount": "50",
  "used_unit": "ml"
}

$ tm aliquot use 8826L401.1 -m "used it all"
Used all 100 ml from 8826L401.1 (consumed): used it all
```

- **`AMOUNT` and `UNIT` come together.** Passing only one is a usage error (exit 2). The unit must
  match the tube's, and the amount may not exceed what is left.
- **Leaving both out uses everything left**; the event records the remaining quantity and unit,
  exactly like passing them explicitly. A tube whose quantity is NULL can only be used whole (the
  event records a NULL amount); a partial use of such a tube is refused.
- **Reaching zero consumes the tube** and clears its box position in the same write (the old position
  stays on the event). `use` is refused only when the tube is already `consumed`.
- **`-m/--message` is required** on both commands. It is trimmed, refused when empty or
  whitespace-only, has no length limit, and is stored on the event (`aliquot_event.note`; new
  `use`/`move` events leave `purpose` NULL). It is event text, never the ASCII commit message.
- `--json` adds `used_amount`, `used_unit` and `message` to the result (`used_amount` is NULL for a
  whole use of a tube with no quantity), as in the middle example above.
- Python API: `ledger.aliquots.use(ref, amount=None, unit=None, *, message)` and
  `ledger.aliquots.move(ref, box=..., slot=..., status=..., message=...)`; the same both-or-neither
  rule and the same empty-message refusal.

**Temporary naming mismatch:** the CLI says `--message`, while the value lives in
`aliquot_event.note`; `tm history --json` keeps the `note`/`purpose` event keys. A follow-up change
aligns the names — this release does not.

## Presets and stock properties

No bundled preset declares statuses any more. Thirteen parts are bumped because they declared or used
a set:

| part | version | part | version |
|---|---|---|---|
| `base` | 4 → **5** | `mouse` | 1 → **2** |
| `bacteria` | 1 → **2** | `nucleic_acids` | 2 → **3** |
| `biosamples` | 1 → **2** | `proteins` | 2 → **3** |
| `c_elegans` | 1 → **2** | `viral_vectors` | 1 → **2** |
| `cell_culture` | 2 → **3** | `zebrafish` | 1 → **2** |
| `drosophila` | 1 → **2** | `library` | 2 → **3** |
| `immuno` | 1 → **2** | | |

The bundles keep their versions (`molbio` 3, `cellbio` 1, `angenet` 1) because their `include:` lists
did not change; the parts inside them carry the new counters.

The detailed life states are **optional enum stock properties** now (no `required:`, no default):

| kind | property | values |
|---|---|---|
| `mouse_cohort`, `fish_group`, `fish_clutch` | `fate` | `euthanized`, `found_dead`, `transferred`, `cancelled` |
| `fly_culture` | `fate` | `discarded`, `lost` |
| `worm_culture` | `condition` | `growing`, `starved`, `contaminated` |

A frozen stock carries no life-state property: it is `stored` in the freezer and `consumed` once it
is thawed. A newly initialised ledger records the new versions; an existing ledger keeps its own
copies until the manual step below replaces them.

## Upgrading a ledger (manual)

There is **no `migrate.py`** for spec 5 → 6. The change touches the ledger's *files* (its preset
copies and any local kinds) as much as its rows, and the row change is a vocabulary remap an operator
has to review. The procedure is
[`migration/spec/5-to-6/README.md`](https://github.com/flmaximwang/Tetramark/blob/v0.8.0/migration/spec/5-to-6/README.md),
and each of the 13 bumped parts has a README-only step folder under `migration/presets/<part>/<N>-to-<N+1>/`.
In order:

1. **Run every pending historical preset step first.** The frozen step scripts under `migration/presets/`
   target spec 5 and install spec-5 preset copies; after this step they would be a second, mixed
   closure.
2. **Replace the ledger's whole preset closure** under `<ledger>/presets/` (and any local `kinds/`)
   with the status-free copies of this checkout — all at once, because a closure that mixes both
   models does not load.
3. **Remap `aliquot.status`** with the table above, writing one `migrated: <old status>` status event
   per remapped aliquot. Past events are never rewritten.
4. **`tm schema plan` / `tm schema apply`** — one commit writes `spec_version` 6, `preset_versions`,
   the fingerprint, the DB `CHECK` and the regenerated `dolt_tests`.
5. **Verify** — `tm schema plan` says "up to date" and `tm check` reports no FAIL. Stock properties
   are **not** backfilled: a stock's aliquots may disagree, so the operator records the fate or
   condition by hand.

The migration runner stops with a pointer to the manual README instead of an obscure counter error
when a ledger is newer than an old step.

## Also included

- **`--where` regex filters.** `tm entity list`, `tm stock list` and `tm box list` accept
  `field~pattern` next to `field=value` (Tetramark-6ms.1). The pattern is a *search* over the
  column's text form, run by the database's regex engine: unanchored, case-sensitive (`(?i)` makes it
  case-insensitive), never matching NULL; a `ref` field matches the id it stores. A `field=value`
  filter is still exact, with the schema's coercion. Filters are repeatable and ANDed; a repeated
  `=`, a mix of `=` and `~` on one field, or an invalid pattern is a usage error naming the filter.
  `tm aliquot list --where` stays exact-only (`status` is filtered with `--status`).

## Unchanged on purpose

- `tm aliquot status`, `tm aliquot add`, `tm stock add`/`edit` and `tm entity add`/`edit` need no
  message — they are reversible bookkeeping, not physical actions.
- `tm aliquot status ALQ NEW --force --note TEXT` is unchanged: it overrides the transition check,
  records `aliquot_event.forced = TRUE`, and is the deliberate way to undo a wrong `consumed`. A tube
  that was consumed by mistake is put back with `tm aliquot move … -m`, which re-places it and
  restores `stored`.
- The core tables, the generated views, box geometry, quantities, units and lineage are untouched.
- `tm history` keeps the `note`/`purpose` event keys; the rename to `message` is a follow-up bead.
