# 0.8.57 — a merged use is reversible again, and a half-migrated ledger cannot claim spec 9

0.8.56 shipped spec 9 with two ways to strand a ledger. A non-fast-forward merge made Dolt's diff
tables present the branch's `use` twice — once at the branch commit, once at the merge commit, whose
diff is taken against its first parent — and the reversal refused with "the Dolt history holds 2
records of that event". And `tm schema apply` decided the counter could move by looking for
`reverts_event_id` alone, so an interrupted 8 → 9 left the ledger recording 9 over a shape that
refuses `revert_use`, with the migration now refusing it forever. Both are fixed here, each with a
real-Dolt regression. No schema change, no preset change, no new event kind.

## A `use` that reached the branch through a merge reverts normally

The event row was always unique; only the history named it twice. The reversal now attributes the
change to the commit that made it (the earliest in `commit_order`), and a later row whose
`from` → `to` repeats the selected step is read as that same physical change rather than as a
second one. So after

```text
tm aliquot use ALQ 50 ml -m "branch use" --yes      # on a ticket branch
git … / dolt …                                      # main moves on, then the branch merges
tm aliquot use ALQ --revert-last -m "undo" --yes    # on main
```

the preview shows the pre-use quantity and the applied reversal restores it. A **genuine** later
quantity, unit, status or placement change still blocks the revert and is still named in the error —
the merge does not excuse it, and a test pins exactly that pair.

## A half-migrated ledger stays at spec 8 until the supported step finishes it

The spec-9 shape is all of it or none of it: the `reverts_event_id` column, the `revert_use`
value in the `event` ENUM, and the UNIQUE/CHECK/self foreign-key constraints. `tm schema apply` now
reads the whole shape before it stamps `spec_version`, so a ledger left half-way by an interrupted
`migration/spec/8-to-9` (`Dolt DDL is not transactional`) keeps its stored counter at 8, keeps its
shape, and stays migratable: rerunning the step adds only the missing pieces and lands it at 9 with
all three constraints. That also means the generated `core_revert_event_allowed` /
`core_revert_event_unique` tests are not installed over a shape the database cannot serve.

## A ledger already stamped 9 by 0.8.56

`migration/spec/8-to-9/README.md` now states the recovery, and it is one statement plus a commit:

```sql
UPDATE `ledger_meta` SET `value` = '8' WHERE `key` = 'spec_version';
```

Check first with `SELECT value FROM ledger_meta WHERE key = 'spec_version'`; if it reads 8 there is
nothing to do. The step refuses a counter other than 8 by design, which is why 0.8.56 stranded it.

- Fast lane (`uv run pytest -q -m fast`): **1102 passed** (~4 s).
- Full lane (`-n 16 --dist worksteal`): **2233 passed / 0 failed / 2 skipped** in 233 s. The two
  skips are the 0.4.2 lab-ledger snapshot, which is not in this checkout.
- `python3 scripts/release_check.py`: five version sources agree at 0.8.57, tag absent, notes present.
- Real-Dolt walkthroughs: a branch `use` merged into a moved `main` (`fast_forward 0`) previews and
  reverts (`Quantity: 8 ul -> 10 ul`, `Reverted use event 3 …`); a ledger with the column but not the
  ENUM or constraints keeps `spec_version` at 8 through `tm schema apply`, still passes `tm check`,
  and then `migrate.py` finishes it to 9 with the three constraints.
- Both regressions fail against 0.8.56's code: the merge one with the original "holds 2 records"
  error, the half-patch one by claiming 9.

## Upgrade

- **No hard break.** `tm aliquot use` still needs `--yes` in scripts, as in 0.8.56; nothing else in
  the CLI changed.
- **Spec 8 ledgers**: the 8 → 9 step is unchanged (`migration/spec/8-to-9/README.md`).
- **Spec 9 ledgers and fresh `tm init` ledgers**: nothing to migrate.
- **A half-migrated ledger stamped 9 by 0.8.56**: set the counter back to 8 as above, then run the
  step; no data is rewritten and every existing event keeps its id.
- No preset change, no command renamed, no documented output shape removed.
