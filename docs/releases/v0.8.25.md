# 0.8.25 — shipped skills carry the version they describe

Both shipped skills, `skills/tetramark/SKILL.md` and `skills/tetramark-schema/SKILL.md`, now state
the Tetramark version they were written against — machine-readable in the YAML frontmatter and
visible on the first screen. A copy that describes another CLI becomes detectable instead of failing
on its first removed command, and the release check refuses to tag a tree where either skill's
version is missing or disagrees with `pyproject.toml`. Additive for the ledger and the CLI: nothing
breaks and nothing needs migrating.

## The stamp

```yaml
version: "0.8.25"      # == [project] version; quoted so YAML keeps it a string
spec: "06-cli"         # tetramark-schema mirrors "02-schema-language"
updated: 2026-11-05    # ISO date the text was stamped
```

- The version **is** the package version: there is no separate skill revision and no `rev:` field.
  A doc-only fix ships with the next release bump, not on its own.
- The first body line repeats it visibly: `> Tetramark 0.8.25 skill — if tm --version differs, use
  the copy at tm skill path.` (the two commands are in backticks in the file).
- The skill text is otherwise unchanged: only the three frontmatter fields and the one visible line
  are new. The primary skill stays within its **150-line whole-file budget**, frontmatter included;
  five body lines were reclaimed by merging adjacent decision-table rows and folding sentences, so
  no command, flag, rule or reference link was dropped. The schema skill stays at its measured
  171-body-line ceiling; the trim is Tetramark-0pj.
- `src/tetramark/skills.py` resolves a skill copy — `$TETRAMARK_SKILLS_DIR`, then the checkout's
  `skills/`, then installed package data — reads its `version:` and classifies it against
  `tm --version` as `match` / `older` / `newer` / `unknown` / `missing`. It is the Dolt-free
  foundation for the `tm skill` commands, not a new CLI surface in this release.

## Guarded at release and in the fast lane

`scripts/release_check.py` (still stdlib-only: the workflow runs it with a bare `python3`) reports
two more sources, `skills/tetramark/SKILL.md` and `skills/tetramark-schema/SKILL.md`, and fails with
`NOT READY`, exit 1 on:

- a missing frontmatter version: `skills/tetramark/SKILL.md does not carry a version`;
- a mismatch: `skills/tetramark/SKILL.md says X, pyproject.toml says Y`.

The regex is `^version:\s*"?([^"\s]+)"?\s*$`, applied to the frontmatter only, so the fenced
`version: 1` preset example in the schema skill's body cannot be mistaken for the stamp.
`tests/test_skill_version.py` runs the same checks in the fast lane. One `SKILL_LINE_BUDGETS` table
in `tests/conftest.py` names the counting mode per skill: the primary skill is capped at 150 lines
in total, frontmatter included, while the schema skill's body is capped at its measured 171 lines,
which may only go down.

## Upgrade

Nothing to migrate: no CLI change, no preset or ledger-format change, and both skills still
describe the same commands. The visible line names `tm skill path`, the command that resolves the
shipped copy; that command lands in 0.8.26, so until then the copy is the checkout's `skills/`
directory.

- Full lane (`uv run pytest`) passes inside the 300 s guard; the absent 0.4.2 lab snapshot is
