# 0.8.16 — Dolt's global ~/.dolt configuration is not a ledger

Running `tm` from `$HOME` — or from any directory with no ledger in it or above it — stopped at
Dolt's global `~/.dolt` configuration directory and reported `is not a ledger … 'tm adopt' formats
an existing bare Dolt database in place`. That directory holds Dolt configuration (`creds/`,
`eventsData/`, `config_global.json`, `version_check.txt`), not a database, and suggesting
`tm adopt ~` on it was wrong. Discovery now recognises a real Dolt database (`.dolt/noms/` or
`.dolt/repo_state.json`) and walks past a config-only `.dolt/`, so the error is the honest
`no ledger found from <cwd> …`. Additive for every real ledger: nothing breaks, nothing needs
migrating and a ledger written by 0.8.15 opens unchanged.

## What changed

- New `is_dolt_database(path)` in `tetramark.driver.resolution`: true when `<path>/.dolt/noms` is a
  directory or `<path>/.dolt/repo_state.json` is a file. These are pure filesystem checks — the
  `dolt` binary is never run and nothing is written into the `.dolt/`.
- The upward walk steps past a `.dolt/` that holds no database instead of raising: from `$HOME`
  (config-only `~/.dolt`) or from any child directory, `tm` exits 2 with
  `no ledger found from <cwd> … Pass --ledger PATH, cd into a ledger directory, or create one with
  'tm init'` — never a `tm adopt` hint.
- An explicit path names the problem: `tm -l ~` (or any config-only `.dolt/`) exits 2 with
  `<target> is not a ledger: its .dolt/ holds no Dolt database (no noms/ or repo_state.json); it
  looks like Dolt's global configuration directory. Pass a ledger directory, cd into one, or create
  one with 'tm init'`.
- A real bare database — `.dolt/noms/` or `.dolt/repo_state.json`, no `ledger.yaml` — keeps today's
  `is not a ledger … 'tm adopt' formats an existing bare Dolt database in place` error, both when
  it is named explicitly and when the walk meets it.
- `tm adopt` on a config-only `.dolt/` is refused before any `dolt` call, with the same
  global-configuration wording; nothing is written into the directory.
- `is_ledger_dir` and `refuse_nested` are unchanged. No schema, preset or ledger-format change; no
  command's output changes for a real ledger.

## Upgrade

Nothing to migrate: `spec_version` stays 6, the ledger format is unchanged, and every command keeps
its options, output and exit codes. The only user-visible difference is the error text for a
directory that is not a ledger — Dolt's global config directory is now named for what it is instead
of being offered to `tm adopt`.
