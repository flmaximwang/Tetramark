# 0.8.3 — explicit purge for entities, stocks and boxes

Three commands now hard-delete an object that was added by mistake — `tm entity purge`,
`tm stock purge` and `tm box purge` — each in exactly one Dolt commit. A purge writes nothing and
exits 1 while anything still references the object; its error names the referents (capped) and the
command that clears them. `tm aliquot purge` also removes the tube's alias rows now, and refuses a
referenced tube with the same friendly error instead of a raw foreign-key failure. Nothing breaks and
nothing needs migrating.

## The three commands

```sh
tm entity purge ID|ALIAS
tm stock purge ID|ALIAS
tm box purge NAME|ID|ALIAS
```

- REF resolves exactly like `show`/`edit`: id, unique id prefix where the object allows one, or an
  alias; a box also by its name. An aliquot id is never shortened, so `tm aliquot purge` takes the
  full id or an alias.
- Each command takes the write lock, supports `--json`, honours the global `--dry-run`/`--no-commit`
  and makes one commit: `purge(entity): …`, `purge(stock): …`, `purge(aliquot): …`, `purge(box): …`.
  The rows leave the tables; Dolt history keeps them, which is the only way back.
- The text line carries the counts, for example
  `Purged stock 8826L401 (1 aliquot(s), 1 event(s) removed)`; `--json` returns
  `{object, id, kind, purged: true, …counts}` (an aliquot has no `kind`; a box also carries `name`).
- The object's alias rows go in the same write, so no `(object_type, alias)` row keeps pointing at a
  deleted object. `tm box purge` also drops the generated `v_box_<name>` view in the same commit, so
  `tm check` never reports an orphan view.
- Python API: `ledger.entities.purge(ref)`, `ledger.stocks.purge(ref)`, `ledger.aliquots.purge(ref)`
  and `ledger.boxes.purge(ref)`.

## What a purge refuses

A purge is explicit and never guesses: while anything still references the object it raises a
business error (exit 1) before writing, and the message lists what blocks it plus the command that
clears it. It checks the core foreign keys **and** user `type: ref` kind fields that point at the
object or its kind.

| Command | Refuses while | Otherwise removes |
|---|---|---|
| `tm entity purge` | a stock points at the entity | the `entity_<kind>` row, aliases, the entity row |
| `tm stock purge` | another stock has `parent_stock_id` = it, a stock names one of its aliquots as `source_aliquot_id`, or a kind `ref` field points at it or one of its aliquots | its own aliquots (each tube's events, aliases and row), then the `stock_<kind>` row, aliases and the stock row |
| `tm aliquot purge` | a stock's `source_aliquot_id` or a kind `ref` field points at the tube | the tube's events, aliases and row |
| `tm box purge` | the box holds an aliquot or a child box | the slot rows, the `box_<kind>` row, aliases, `v_box_<name>` and the box row |

A stock's own tubes belong to it, so they cascade with it. Everything else is a refusal, never a
cascade: a box is emptied only by `tm aliquot move` / `tm box move` (or by purging its contents).
`aliquot_event.from_box_id`/`to_box_id` have no foreign key, so purging a box leaves those history
rows alone.

The remedy is a command: `tm stock purge REF`, `tm entity edit REF --set FIELD=OTHER-ID`,
`tm aliquot move ALQ --box NAME --slot SLOT -m MSG`, `tm box move NAME --in PARENT`. A box kind
`ref` field has no edit command at all, so that remedy says to purge the empty holder box
(`tm box purge`) and create it again without the field.

```
$ tm entity purge rea
Error: cannot purge entity '5daa2c7a-1772-40b4-9c59-1f235298c2b4': 1 other object still
references it: stock 8826L401 (entity_id); purge its stocks first: tm stock purge 8826L401

$ tm stock purge 8826L401
Purged stock 8826L401 (1 aliquot(s), 1 event(s) removed)

$ tm box purge RACK-A
Purged box RACK-A (10 slot(s), 0 alias(es) removed)
```

## Aliquot purge now cleans aliases and refuses references

`tm aliquot purge ALQ` used to delete the tube's events and row, leaving its alias rows dangling and
letting a referencing `source_aliquot_id` surface as a raw foreign-key error. It now deletes the
aliases in the same write and refuses a referenced tube with the same business error as the other
purges, naming the stock (or kind field) that blocks it. The result gains an `aliases` count.

## Upgrade

Nothing to migrate: `spec_version` stays 6 and the ledger format is unchanged. The new `--json` keys
and the new commands are additive; a ledger written by 0.8.1/0.8.2 opens unchanged.
