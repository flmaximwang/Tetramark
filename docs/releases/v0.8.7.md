# 0.8.7 — `tm alias add box` accepts the box's name

`tm alias add box RACK-A ra` now works: the box is resolved by its human name before the id, alias
and unique-prefix rules, the same order as `tm box show`, `tm box move` and `--box`. `box.name` is
`NOT NULL UNIQUE`, so the lookup is unambiguous. Additive: nothing breaks and nothing needs
migrating.

## The name is the reference

Before this release `tm alias add box` accepted a full id, an exact alias or a unique id prefix, so
a box's human name failed with `unknown box 'RACK-A'` even though every other box command takes it.

```console
$ tm box add rack RACK-A
Created box RACK-A (rack) with 10 slot(s)
$ tm alias add box RACK-A ra
Alias ra -> box 5b11…
$ tm box show ra --json
{"id": "5b11…", "box": "RACK-A", "aliases": ["ra"], …}
```

- Box ref precedence is `_resolve_box`'s: exact name, then full id, then exact alias, then unique id
  prefix — a box name beats another box's alias or id prefix.
- `--json` reports the canonical box id as `object_id`, and the write is still one Dolt commit.
- A ref that matches nothing keeps `unknown box 'REF'; try tm find REF` (exit 1); an ambiguous id
  prefix is still a usage error (exit 2) with no hint.
- Other object types are unchanged: `entity.name` is nullable and non-unique, `aliquot.label` is
  non-unique and `stock` has no name column, so `tm alias add entity|stock|aliquot` still resolves
  by id, alias and unique id prefix only.
- `tm alias remove` is unchanged. It takes the alias text, not an object ref, so the "remove" half of
  the bug title was never a defect.
- `tm alias add --help`, `docs/spec/06-cli.md` and `skills/tetramark/references/commands.md` now say
  a box `REF` may be its name.

## Upgrade

Nothing to migrate: no schema or ledger-format change, `spec_version` stays 6, and a ledger written
by 0.8.6 opens unchanged.
