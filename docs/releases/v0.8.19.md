# 0.8.19 — test harness: the per-query oracle runs again

0.8.19 is internal only: it changes tests, version files and release notes. Nothing in `src/`, the
CLI, the Python API, the ledger format, the specs or the skill content moves, and no assertion is
removed or loosened.

The rare `int`/`str` `seq` mismatch in the batched-vs-per-query read test was not a thread race. Two
harness defects produced it: `per_query_path` had lost the `monkeypatch.setattr` that installs the
per-query path (so both phases of the comparison ran the batch), and the list/csv/lineage module
fixtures built their rows through the server backend and left that `dolt sql-server` cached and alive.
Dolt routes an embedded `dolt sql -r json` through a live server for the same database, and the server
reports integer columns as JSON strings, so the "embedded" reads could return `'1'` instead of `1`.
The test now runs both paths for real and no server exists when the embedded reads run.

## What changed

- `tests/test_list_round_trips.py::per_query_path` installs its
  `monkeypatch.setattr(EmbeddedDriver, "query_many", per_query)` again: the comparison compares the
  batch with the historical per-statement path instead of running the batch twice.
- The loop variable in `test_unknown_refs_keep_their_errors` is renamed so `True` means the per-query
  path.
- The `read_ledger`, `source` and `template` module fixtures call
  `tetramark.driver.server.discard_server(<path>)` after the server-built `ledger.close()` and assert
  that `<path>/.dolt/sql-server.info` is absent before the embedded reopen.
- New guards: `test_per_query_path_replaces_query_many` (AC1) fails if the patch goes away, and
  `test_embedded_fixture_reads_typed_integers` (AC3) fails if a cached server survives the fixture.

The product-side behaviour — an embedded read returning string integers while a user-run
`dolt sql-server` is alive — is unchanged and stays open as the follow-up bead **Tetramark-2gz**
(embedded reads return string integers when a user-run dolt sql-server is alive).

## Upgrade

Nothing to migrate: `spec_version` stays 6 and the ledger format is unchanged. A ledger written by any
0.8.x release opens unchanged.
